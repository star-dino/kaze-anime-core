# 08 AI 多代理制作方法论：CONTRACT.md 是怎么让 8 个 AI 一起拍片的

> 对应原作：两个仓库的 `CONTRACT.md`（Sunshower 约 10 KB，LEVIATHAN 约 15 KB）与 README 的 “How it was made”。
> 模板：[`templates/CONTRACT_模板.md`](../templates/CONTRACT_模板.md)、[`templates/新故事开工清单.md`](../templates/新故事开工清单.md)。

## 8.1 组织形式

> “One director session and parallel agent teams in Claude Code, working from a shared production bible (CONTRACT.md): archer, leviathan, ships, world, underwater, energy FX, water FX, sound. Each team owned its own files and rendered stills to check its shots against the reference.” —— LEVIATHAN README

```
             ┌─────────────── 导演会话（主 Claude Code 会话）───────────────┐
             │ 拥有：engine / glsl / materials / shots(CUES+SHOTS) / util / │
             │       main / index.html / tools                              │
             │ 职责：写 CONTRACT、定节拍、搭骨架、整合、裁决、最终渲染        │
             └──────┬───────┬───────┬───────┬───────┬───────┬───────┬──────┘
                    │       │       │       │       │       │       │
                 World  Archer  Leviathan Ships Underwater FX-Energy FX-Water  Sound
              （每个都是并行的 agent，只能改自己名下的文件，用静帧自审）
```

Sunshower 的部门：导演、环境、水与光特效、鸟、声音、交付。LEVIATHAN：导演、世界、弓兵、利维坦、船队、水下、能量特效、水特效、声音。

## 8.2 CONTRACT 的结构（逐节拆解）

两份 CONTRACT 的章节几乎一样，这就是一份可复用的“制片合同”模板：

| 章节 | 写什么 | 原作例子 |
|---|---|---|
| **规格** | 时长、帧率、分辨率、技术栈、怎么采集、怎么交付 | “An 83-second, 24 fps, 1920×1040 anime short rendered in the browser with three.js r170 (WebGL2), captured frame by frame with headless Chrome and encoded with ffmpeg” |
| **参考** | 参考素材在哪、怎么用 | “OPEN THE REFERENCE FRAMES OF YOUR SHOTS with the Read tool before you start and match their composition, subject placement, lens feel and camera move” |
| **继承** | 复用哪些已有代码、先读哪些文件 | “The engine and tooling come from our previous film … Read how it solved things before inventing new ways: robot.js (convex-hull armour…)” |
| **美术指导（客户原话，照字面执行）** | 要什么、**不要什么**、被否决过什么 | “It must NOT read as CGI, vector art, or Minecraft blocks.” “The client rejected ‘clean, boxy, Minecraft’ looks twice.” |
| **故事** | 一段话讲清楚整个故事 | |
| **设计** | 每个角色/道具的设计描述 + 尺寸 | “Archer (~110 m tall): sleek silver-steel humanoid, angular overlapping armour plates like a samurai-gundam…” |
| **镜头表** | id / 名字 / 时间 / 场景 / 负责部门 / 画面内容 | 39 行的表 |
| **世界布局与尺度** | 坐标系、谁站在哪、朝哪、太阳在哪、多大 | “Robot pelvis ≈ y -0.45, stands at the origin facing -Z; its LEFT side … is world -X” |
| **部门与文件所有权** | 谁拥有哪些文件 | “Never edit, reformat or ‘fix’ a file you don't own; put requests in your report.” |
| **镜头/look 接口** | 镜头函数签名、look 字段 | `CAMS = { s05: (lt, d, t, st) => ({ pos, look, fov, roll?, near?, far? }) }` |
| **部门 API** | 别人可以依赖什么 | `ctx.leviathan.pose(p)`、`anchor(name)`、`makeWhale(opts)`、`ctx.ships.fleet`… |
| **引擎事实** | pass 顺序、id 规则、材质参数、纯函数规则、性能预算 | “Everything must be a pure function of state.t / CUES … no Math.random”；“a typical frame under ~0.4 s at --scale 2” |
| **怎么运行和检查** | 精确的命令行 | `node tools/snap.mjs --scale 1 --out out/<dept> --sheet name s:foot t:12.4 f:300` |

## 8.3 为什么这套方法有效

1. **先定接口，后写实现**。锚点名、`ctx` 上的 API、`look` 字段、id 段落在动工前写死。水特效部门不需要知道弓兵怎么建模，只需要 `ctx.archer.anchor('arrowTip', v)`。
2. **单一时间真相**。所有部门读 `CUES`，“Exact times are in CUES — never hard-code copies”。导演改时间，所有部门自动同步。
3. **文件所有权 = 没有合并冲突**。8 个 agent 同时写代码，从不改同一个文件。需要别人改东西？写进自己的最终报告，由导演协调。
4. **容错加载**。一个部门崩了，其他部门照常出图（`NOOP` 回退）。
5. **默认机位兜底**。LEVIATHAN 每个场景有 `DEFAULT_CAM`，没人认领的镜头也能渲染 —— 全片从第一天起就是“完整可看的”，只是越来越好。
6. **视觉自审**。agent 用 `snap.mjs` 出静帧，再用 Read 工具“看”图（多模态），和参考帧对比。CONTRACT 反复强调“judge critically”。
7. **把美术意见写成可执行的约束**。不是“好看一点”，而是“暗部用冷薰衣草蓝，绝不用灰”、“人物一拍二，水一拍三”、“不能浮空：接触和尺度必须读得出”。
8. **把历史教训写进去**。“The client rejected … twice”、“The film was re-directed: it is now a BRIGHT SUMMER AFTERNOON”—— 合同是活文档，新加入的 agent 一读就知道雷区在哪。
9. **进度可见**：“Save your current best stills to out/<dept>/latest/ as you go: the client asks to see progress.”

## 8.4 美术指导的写法（可直接抄的句式）

从两份 CONTRACT 里提炼：

- **正向 + 负向同时给**：“Bright, eye-catching, high-key … Drama comes from scale and contrast, never from murk.”
- **点名风格参照**：“hand-drawn theatrical anime (Ghibli-style painted gouache backgrounds + crisp cel-shaded character with ink lines)”
- **列出禁止项**：“No plastic shading, no visible polygons, no perfect geometric shapes, no smooth software easing on characters, no constant bobbing.”
- **给出颜色词汇**：“deep-blue sky, towering white cumulus with lavender shadow sides, cobalt-to-turquoise sea, white foam”
- **给出运动规则**：“Characters animate on twos, water FX on threes, held poses, snappy accents; huge things move slowly with mass. Natural joint motion, no breaking wrists, no sliding.”
- **给出情绪**：“tender, bright, nostalgic, a little funny — a short you rewatch and share”
- **给出光的设计**：“Rain is BACKLIT (the sun is behind the robot in the front shots), so it glitters.”
- **给出可测量的几何**：彩虹“primary radius 42°, faint secondary at 51° → its top is ~18° above the horizon”。

## 8.5 用 Claude Code 复刻这套流程（建议做法）

**阶段 0 —— 前期（导演会话，你 + 主 Claude）**
1. 写一页故事；拆成 6–12 个节拍 → `CUES`。
2. 写镜头表（每镜：时间、场景、负责部门、画面内容、镜头运动、参考）。
3. 写角色/场景设计（文字 + 尺寸 + 配色）。
4. 用 [`templates/CONTRACT_模板.md`](../templates/CONTRACT_模板.md) 填出 CONTRACT。

**阶段 1 —— 骨架（导演会话）**
5. 从 `anime-core` 复制引擎，新建 `src/story/<新故事>/`：`story.js`（CUES、SHOTS 用占位机位、默认 look）、空的部门文件（`export function createX(ctx){ return { update(){} }; }`）。
6. `check.mjs` 零报错、`snap.mjs` 能出每个镜头的（空）静帧 → 骨架完成。

**阶段 2 —— 并行部门（多个 agent）**
7. 为每个部门开一个子 agent（Claude Code 的 Agent 工具；需要隔离时用 worktree），提示词模板：

```text
你是《<片名>》的 <部门> 部门。先完整阅读 CONTRACT.md（尤其“美术指导”“部门与文件所有权”“引擎事实”）。
你只能修改：<文件列表>。需要其他部门改动时，写进最终报告，不要自己改。
你负责的镜头：<id 列表>。开工前用 Read 打开这些镜头的参考图。
每次修改后：
  1) node tools/check.mjs 60  —— 必须零报错
  2) node tools/snap.mjs --scale 1 --out out/<部门> --sheet review <你的镜头的 s:/t: 列表>
  3) 用 Read 打开 out/<部门>/review.jpg，严格对照美术指导和参考图自评，列出问题再改
把当前最好的静帧存到 out/<部门>/latest/。
完成时报告：做了什么、还差什么、需要其他部门做什么、你发布了哪些锚点/API。
```

**阶段 3 —— 整合（导演会话）**
8. 读各部门报告，处理跨部门请求，调整 CUES，全片联系表审片（每镜头 2–3 张）。

**阶段 4 —— 声音（声音部门 agent）**
9. 读 CUES，写速度图和音效；出频谱图自审。

**阶段 5 —— 渲染与交付**
10. `npm run build`（配乐 → 整片 → 播放器）。

## 8.6 常见失败模式（以及合同里怎么预防）

| 失败 | 预防条款 |
|---|---|
| agent 顺手“修”了别人的文件，覆盖了对方的工作 | 文件所有权表 + “Never edit, reformat or fix a file you don't own” |
| 特效贴在硬编码坐标上，角色一改就错位 | “always read anchors, never hard-code positions” |
| 用 `Math.random()` / 累积状态 → 乱序渲染时闪烁、续渲接缝 | “pure function of state.t / CUES … no Math.random”（最好再加 lint） |
| 时间写死副本，导演改节拍后不同步 | “Exact times are in CUES — never hard-code copies” |
| 物体漂浮、比例不对 | “never let things float: contact and scale must read” |
| 描线 id 冲突、颜色约定不一致 | id 分段表；颜色空间约定（见 02 §2.11） |
| 某个镜头慢到渲不动 | 性能预算 + “visible = false on its groups when its set is not active” |
| 风格漂移成 CG 感 | 负向清单 + 被否决历史 + 参考帧对比 |
