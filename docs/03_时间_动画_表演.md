# 03 时间、动画与表演

> 对应原作：`src/shots.js`、`src/util.js`、`src/robot.js`（IK）、`src/kingfisher3d.js`（原画式表演）、LEVIATHAN `src/archer-pose.js`、`src/lev-spine.js`、`src/lev-anim.js`、`src/cams/*.js`。
> 对应 anime-core：`src/core/film.js`、`util.js`、`kit.js`，`src/story/story.js`、`dino.js`。

## 3.1 铁律：每一帧都是时间的纯函数

CONTRACT 原文：

> `update` is called once per rendered frame, in any order of frames (random access!) — never accumulate state across calls; derive everything from `state.t` and `CUES` deterministically (seeded RNG in `src/util.js`, no Math.random).

它换来了什么：

| 能力 | 为什么依赖“纯函数” |
|---|---|
| 工作台可以随意拖时间轴 | 跳到第 700 帧不需要先算前 699 帧 |
| 渲染可以分段、断点续渲 | 第 3 段崩了，重跑只渲第 3 段，和之前的段无缝衔接 |
| 多个浏览器页面并行渲染 | 每页渲不同段，结果一致 |
| 静帧审片 | `snap.mjs t:26.4` 直接出那一帧 |
| 音频能“看”画面 | 音频工具逐帧调用 `stateFor(f)` 采样锚点位置做声像（见 06） |
| 可复现 | 同一份源码永远渲出同一部片（render.mjs 用源码哈希判断旧段是否需要重渲） |

**怎么写才算“纯”**：
- 随机数：`hash(i, drawing, k)` 或种子 `Rng`，永远不用 `Math.random()`。
- 粒子：不存位置、不积分速度；用闭式解 `p = p0 + v·a + ½g·a²`（`a = t - 出生时间`）。
- 周期事件（雨滴、白浪）：`cyc = floor((t + 相位)/周期)`，用 `cyc` 当种子决定这一轮的位置。
- 每帧开头把所有批次清空（`begin()`），按 t 重新填。

> 我在审读中发现原作唯一的一处违规：Sunshower `robot.js` 第 320 行，机器人身上苔藓/花的色相偏移用了 `Math.random() * 0.2`。每次打开页面颜色都会略有不同；渲染工具在崩溃重启浏览器后，前后两段的苔藓颜色可能对不上。很小，但正是这种问题需要用 lint 规则（禁止 `Math.random`）在引擎层堵死。

## 3.2 CUES：全片唯一的时间真相

```js
// Sunshower src/shots.js
// Story beats in film seconds. fx.js, birds.js and the soundtrack all key off
// these, so changing a time here re-times every department at once.
export const CUES = {
  kfPreen: [6.0, 7.4], kfHop: 8.6, cloudVeil: 10.0, firstDrop: 10.4, dropOnBird: 13.2,
  rainFull: 15.6, robotLookUp: [15.8, 17.4], roofStart: 20.2, roofOver: 23.2,
  kfShake: 26.2, kfFluff: 27.4, eyesBlink: 28.4, sunBurst: 31.0, rainbowStart: 31.2, rainbowFull: 34.0,
  beacons: [37.6, 38.2], kfTakeoff: 38.8, wave: [39.3, 40.7], fadeOutStart: 40.2, ...
};
```

- 画面：翠鸟的原画表、机器人的手、雨量曲线、彩虹生长、信标闪光都读它；
- 声音：**音乐的速度图（tempo map）直接锚在 CUES 上**（翠鸟的小跳落在强拍、太阳出来在强拍、两次信标闪光和起飞是连续三拍……），见 06；
- 工具：音频频谱图上自动标注每个 CUE，人可以“看”声音对不对位。

改一个数字，全片所有部门同时跟着改。这是**让多个 AI agent 并行工作而不互相打架的关键**：没人需要知道别人的代码，只需要读同一张表。

## 3.3 SHOTS 与状态对象

**Sunshower**：镜头写在一个数组里，每个镜头带一个相机函数：

```js
{ name: 'umbrella', start: 20, end: 25,
  cam: (lt, d) => ({ pos: lerp3([-4.3, 1.6, -6.9], [-4.0, 1.6, -6.4], easeInOut(lt / d)), look: [-0.35, 1.75, -1.5], fov: 32 }) },
```

`lt` = 镜头内秒数，`d` = 镜头长度。几乎所有镜头都是“慢推”或“静止 + 极小漂移”—— 动画的镜头语言。

**LEVIATHAN**：39 个镜头，相机和 look 由**拥有该镜头的部门**各自写在 `src/cams/<部门>.js`，导演用注册表合并：

```js
// shots.js
{ id: 's15', name: 'whales', set: 'deck', owner: 'monster', start: 23.17, end: 26.97 },
export function registerCams(mod) { Object.assign(CAMS, mod.CAMS || {}); Object.assign(LOOKS, mod.LOOKS || {}); }
// 还没人认领的镜头有按场景的默认机位 DEFAULT_CAM[set]，所以整片随时可以完整渲染
```

`set` 字段决定哪个场景可见：“Only one set is on screen at a time … every department must set visible = false on its groups when its set is not active, so sets can overlap in space and frames stay fast.”

**状态对象 `st`**（每帧由 `evalFrame(frame)` 生成，传给所有部门的 `update(st)`）：

```js
{ frame, t, si, shot, lt, dur, cues,
  look: { k, sunElev, sunAz, shafts, rain, rainbow, key, shadow, inkWidth, ... },
  cam: { pos, look, fov, roll, near, far },
  fade, fadeColor, shadow, key,
  // 故事专属：Sunshower 有 pose, eyes, beacon, wet, rain, rainbow, veil；LEVIATHAN 有 set, sid
}
```

anime-core 把这一层抽成 `createTimeline(story)`（`src/core/film.js`），故事只提供 `cues / shots / look / state(st)`。

## 3.4 动画的“拍数”：一拍二、一拍三

```js
export const onTwos   = (t) => Math.floor(t * 12 + 1e-6) / 12;   // 角色：12 张/秒
export const onThrees = (t) => Math.floor(t * 8  + 1e-6) / 8;    // 水、能量特效：8 张/秒
```

- 角色的姿态函数都先做 `ta = onTwos(t)` 再算 —— 24 fps 的视频里每张“原画”停 2 帧，动作有日本 TV/剧场动画的顿挫感。CONTRACT 明确禁止“smooth software easing on characters, no constant bobbing”。
- 水面动画时间 `uFxTime = floor(t*8)/8`；闪电每“张原画”（8 fps）重新生成形状：“so it flicks like hand-animated lightning instead of boiling”。
- 笔压噪声种子 `floor(t*12)%5`：描线随原画轻微变化。
- **重新起拍**：LEVIATHAN 弓弦松开的瞬间必须正好落在它自己那一帧上：

```js
// archer-pose.js
export function drawingTime(t) {
  const r = CUES.release;
  return t < r ? onTwos(t) : r + onTwos(t - r);    // 松手之后从 release 重新数拍
}
```

- **例外是“打在一拍一（on ones）”**：快速的甩动（翠鸟抖水：`A B A B A B A B C C C C` 每帧换一张）用 24 张/秒，这也是动画的惯例：快动作上一拍一。

## 3.5 表演：用“原画表”而不是关键帧曲线

Sunshower 翠鸟的表演是一张 **[时间, 原画名]** 表（`kingfisher3d.js` 的 `kfScript`），每张原画是一个完整姿态（`DRAW` 字典）：

```js
[c.dropOnBird, 'squint'], [c.dropOnBird + 0.25, 'perchHalf'], [c.dropOnBird + 0.33, 'perchBlink'],
[c.dropOnBird + 0.41, 'perch'], [c.dropOnBird + 0.6, 'lookUp'], ...
const DRAW = {
  squint: { tilt: 38, hPitch: -18, sink: 0.7, eye: 'squint', puff: 0.15, camYaw: 0.15 },
  wetHunch: { wet: 1, tilt: 54, sink: 1, hPitch: -10, eye: 'half', droop: 1, tail: -10, sleek: 1 },
  fluffHappy: { tilt: 54, puff: 1, fluffy: 1, sink: 1.2, hRoll: -12, eye: 'happy', camYaw: 0.25 }, ...
};
```

- 原画之间**不插值**（保持 = hold），只在切换时插入**一张中间画**（breakdown）：新原画的第一张画是“旧 → 新 62%”，然后跳到新姿态。这就是手绘动画的 key + breakdown。
- 连续量（身体倾角、头的俯仰、蓬松度）在原画间混合；离散量（眼睛形状 open/half/closed/squint/happy、腿的状态）直接切换。
- 眨眼 = 只有一两张画的 `perchBlink`；被雨滴砸到 = `squint` + 0.17 秒的压扁 `squash 0.88`。
- `camYaw`：“朝镜头看”的分量 —— 角色会根据当前相机位置转头卖萌（动画里经常“看镜头”）。

这套写法对 AI 极其友好：**表演 = 一张人能读懂的时间表**，改一个表情只需改一行。

## 3.6 机器人的表演：IK 目标 + 弧线 + 重量感

```js
// shots.js robotAt(t)
const ta = onTwos(t);
const p = JSON.parse(JSON.stringify(BASE));
p.ikL.w = addV(p.ikL.w, [0, noise1(ta * 0.35, 3) * 0.015, 0]);   // 静止时极轻的漂移：不像“冻住”
// 右手出水 → 经过高处外侧的中转点 → 盖到鸟上方（二次贝塞尔弧线，手腕方向也一起过中转点）
let r = mixIK(BASE.ikR, REST_R, k1);
r = arcIK(r, MID_R, ROOF, k2);
const over = Math.sin(clamp(invLerp(c.roofOver - 0.2, c.roofOver + 0.8, ta)) * Math.PI) * 0.05;
r.w = addV(r.w, [0, -over, 0]);                                    // 重量：先沉一下再稳住
```

- 手臂用 **IK 目标**表达（`w` 手腕位置、`f` 手指方向、`n` 掌心朝向、`pole` 肘部朝向、`follow` 手腕跟随前臂的比例），而不是关节角 —— 对写表演的人（和 AI）更直观：“把手放到鸟头上方 30 cm”。
- **弧线**：大动作走弧线不走直线（动画原理 Arcs）。
- **重量**：落位时的小下沉和回弹（Follow-through）。
- `follow: 0.7`：“bends the desired finger direction toward the forearm line so the wrist never snaps”—— 解决 IK 常见的“折手腕”。

**两骨 IK**（`robot.js solveArm` / LEVIATHAN 通用版 `solve2`）：余弦定理求肘位置，极向量定肘的朝向，再用 `makeBasis` 构造世界旋转、换算成父空间的局部四元数。anime-core 的 `kit.js` 收录了 LEVIATHAN 的通用版。

**接触**：翠鸟的脚每帧对机器人左手做射线检测，找手指弧顶的最高点（`crest()`）作为落脚点，脚趾卷在上面 —— “never let things float: contact and scale must read”。

## 3.7 巨物的动画（LEVIATHAN）

### 弓兵：力量感来自“抖”和“沉”
```js
const draw = track([[0, 0.0], [0.67, 0.17], [1.47, 0.28], [2.6, 0.4], [6.0, 0.62], [9.17, 0.8], [11.8, 0.97], [CUES.release, 1.0]], q);
const breath = Math.sin(q * 1.15) * 0.018;                   // 巨人的慢呼吸
const shake = released ? 0 : 0.004 + 0.016 * draw * draw;    // 拉得越满抖得越厉害
const trem = (s) => noise1(q * 7.3, s) * shake;
```
松手后的后坐用 `easeOut` 甩出去再“settles with mass”。镜头同时做指数衰减的抖动：`a = 1.6 * Math.exp(-rel * 2.6)`。

### 利维坦：一整条 GPU 弯曲的脊柱（`lev-spine.js`）
- 所有网格在“静止空间”里建模：z 轴是脊柱（0 尾 → L 头），x/y 是截面。
- 顶点着色器里把每个顶点“包”到 48 根骨头的 Catmull-Rom 脊柱上（`uBP[48]` 位置+截面缩放，`uBQ[48]` 四元数）→ **整条 900 m 的身体作为一个连续曲面弯曲，CPU 零开销**。
- 三种驱动方式：`fromPath(fn)` 把脊柱铺在一条曲线上；`fromCurl(c, base, pos, k)` 从中间骨头按“每段曲率”正向运动学展开；`fromRoot` 给鳍/尾这种短链。
- 下颌是一个“铰链权重”顶点属性，顶点着色器里绕铰链旋转 —— 嘴真的能张开。

### 原画式的“身体曲线”（`lev-anim.js`）
```js
// 关键帧不是关节角，而是“这一张原画里身体是哪条曲线”（尾→头的 5 个控制点），
// 关键帧之间用 Hermite 样条（连续不停顿），脊柱按“弧长”铺到曲线上 → 身体永远不会被拉长
const flipKeys = vecCurve([
  [76.4, fk([[-60, -700], [-30, -450], [0, -200], [40, 60], [80, 320]])],
  [77.0, fk([[-175, -260], [-110, 0], [-20, 215], [70, 370], [140, 520]])], ...
]);
// “形状来自原画，重心是弹道的”：把曲线整体平移，使重心走抛物线 → 爬升、减速、仰面落下
function flipFall(t) { const f = flipKeys(t), q = t - 77.75, y = 290 - 104 * q * q; ... }
```
破水（breach）同理：身体沿一条**弹道抛物线**头先出水，“so the crown stays where it broke”。头骨部分“is bone”：超过 `skull` 参数的部分沿颈部切线直线伸出，不跟着曲线弯。

这几招（曲线原画 + 弧长铺设 + 弹道重心 + 刚性头骨）可以直接复用到任何“长条巨物”：龙、蛇、鲸、触手、列车。

## 3.8 镜头语言

| 手法 | 原作例子 |
|---|---|
| 长焦压缩巨物 | LEVIATHAN s05 脚踩浪花 `fov: 9`，s06 蓄力特写 `fov: 14` |
| 低机位仰拍显大 | s18 诱饵鲸 `pos y=12`，看向 96–124 m 高处 |
| 慢推 | 几乎所有镜头 `lerp(from, to, lt/d)`，幅度 3–10% |
| 冲击震动 | 放箭 `noise1 × 1.6 × exp(-2.6·dt)`；利维坦翻身 `shake(lt, lt > 2 ? 1.6 : 0.5, 6)` |
| 手持/船上 | s15 甲板 `roll: 0.7 * Math.sin(lt * 0.8)` + 高度噪声 |
| 荷兰角 | s02 弓臂特写 `roll: -23` |
| 统一偏移 | `const OX = -10; // every framing below was laid out with the robot 10 m further inland` —— 角色挪位置后，所有镜头一次性平移 |
| 尺度作弊 | `Spine.setScale(k)`：“a size cheat for single shots”；“Keep everything within 8000 m of the camera … cheat distances and use fog” |
| 每镜头近远裁剪面 | `cam.near / cam.far`（轨道镜头 far=9000） |

**自由机位测试**：`index.html?test=1&cam=x,y,z&at=x,y,z&fov=35&t=10` —— 不改代码就能从任意位置看任意时刻，用来找构图、检查布景穿帮。我在 anime-core 里就是用它一次出 4 个候选机位、看联系表选构图的（见 10）。

## 3.9 给 AI 写表演的建议（从原作提炼）

1. **用 CUES 命名的节拍写一切**，不要写裸数字（`c.roofOver - 0.2`，不是 `23.0`）。
2. **姿态用“人能读懂的参数”**：IK 目标、`tilt/hPitch/puff/eye` 这种语义参数，而不是 40 个关节角。
3. **表演 = 原画表**：`[[时间, 原画名], ...]` + `DRAW = { 原画名: 参数 }`。
4. **先 hold、再 breakdown、关键动作上一拍一**。
5. **重量与接触**：落位下沉、射线找落脚点、巨物重心走弹道。
6. **改完必须出静帧看**（下一节工具），动画的问题十有八九“看一眼就知道”。
