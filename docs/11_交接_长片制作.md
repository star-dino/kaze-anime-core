# 11 长片制作指南：用 anime-core 制作 70–100 秒的原创日式动画短片

> 先读本文与根目录 [`AGENTS.md`](../AGENTS.md)，再读 [`../README.md`](../README.md)、[`10_示例引擎使用说明.md`](10_示例引擎使用说明.md)；遇到原理问题查 `02`–`06`。
>
> **内置长片案例**：《海岬的测风人》（`src/films/cape-keeper/`，100 秒 / 15 镜慢节奏版），分镜与节拍表见 [`../src/films/cape-keeper/storyboard.md`](../src/films/cape-keeper/storyboard.md)。
> **经验法则**：本引擎的强项是**硬表面凸包零件拼装的机甲或器物**（配水粉手绘自然背景）；圆润软体生物（`SoftBody`）建议用于中远景或小配角。
> 开发新故事时，遵循“故事层不改 `src/core/`，通用新能力经回归测试后再合入 `core`”的边界约定。

---

## 1. 目标

| 项 | 要求 |
|---|---|
| 片长 | 约 70 秒（60–80 秒都可以），24 fps，1920×1040 |
| 风格 | 日式动画（赛璐璐角色 + 水粉手绘背景）：夏日、天空、积云、海、草木、光 |
| 题材 | **原创**（例外：《海岬的测风人》的机器人造型经用户拍板，照 *The Moss Keeper*（ChetasLua，原作允许 remix）做，片尾注明“造型参考自”）。主角**不是人**，并且优先是**硬零件做的机器人或器物**（引擎的强项）；毛茸茸的动物只做配角或远景。**不要**复刻任何现有动画作品的角色、场景、标志性镜头 |
| 结构 | 建议 20–30 个镜头、2–4 个场景，有起承转合，结尾有情绪落点 |
| 交付 | `out/<片名>/<片名>.mp4`（带配乐）+ `dist/<片名>.html`（单文件播放器）；配乐、海报、静帧、分段都在 `out/<片名>/` |

## 2. 分工：目录边界

| 区域 | 职责 | 说明 |
|---|---|---|
| `src/films/<片名>/`（新建） | **故事层** | 故事、镜头、角色、布景、特效、配乐全部写在这里 |
| `src/main.js` | 不用改 | 用 `?story=<片名>`（浏览器）或环境变量 `STORY=<片名>`（所有工具）加载 `src/films/<片名>/story.js` |
| `src/core/`、`tools/`、`index.html` | **引擎核心** | 做具体影片时不直接改；通用新能力先在 `_coretest` 做回归验证后再合入 |
| `src/story/`（星星恐龙示例） | 保留不动 | 当作参考写法；可以 import 里面的工具函数，但不要改 |

为什么这样分：core 里有“每帧是时间的纯函数”“MRT 数据协议”“颜色空间”这类全局约定，一处改坏，所有镜头都会出错，而且很难查。故事层改坏了，只会影响自己。

新片的起步方式：把 `src/story/` 整个复制成 `src/films/<片名>/`，复制后各文件里的 `'../core/xxx.js'` 要改成 `'../../core/xxx.js'`。之后所有命令前面加 `STORY=<片名>`，例如 `STORY=cape-keeper npm run check`。浏览器预览：`index.html?story=<片名>`。

## 3. 红线（违反任何一条，成片都会出问题）

1. **不能有随机和时钟**：`Math.random`、`Date.now`、`performance.now` 一律不准用（`npm run determinism` 会扫描出来）。随机数用 `new Rng(seed)`（core/util.js）或无状态的 `hash(a,b,c)` / `hr(a,b,c,lo,hi)`。
2. **画面只能由时间决定**：`update(st)` 里不能累积状态（比如 `x += v`）。位置要写成 t 的函数。需要“惯性/晃动”时用 `core/secondary.js`（见 §5），它在内部保证了这一点。
3. **镜头首尾相接**：`shots[i].start === shots[i-1].end`，最后一个镜头的 `end === duration`。
4. **动作要一拍二**：角色表演的时间先过 `onTwos(t)`，特效用 `onThrees`。不这样做，动作会显得像 3D 游戏而不像动画。
5. **颜色**：角色的设定色用 `screenAll({...})`（core/color.js）把“屏幕上想要的颜色”换算成材质颜色，否则屏幕上会比你写的深、艳。
6. **材质 id**：0 = 绘画背景（吃笔触、不描线）；1–99 = 赛璐璐角色（自动描线）；100+ = 赛璐璐但不描线。同一个角色内部的色块用 `celMaterial({ pattern })` 画在着色器里，不要拆成不同 id（会在交界处出黑线）。
7. **所有部门的 `create` 都要捕获自己的错**：运行时会把加载失败的部门变成空操作，片子能出但会缺东西。每次改完必须跑 `npm run check`，看到 `(no errors)` 才算数。

## 4. 工作流程

```
分镜（storyboard.md）→ 阶段审片 ①
  → 每个场景先做 1 个代表镜头 → 出静帧 → 阶段审片 ②
  → 铺完所有镜头 → 全片联系表 + 粗渲（scale 0.5）→ 阶段审片 ③
  → 配乐对点 → 正式渲染（scale 2）→ 阶段审片 ④ → 交付
```

### 4.1 分镜格式（`src/films/<片名>/storyboard.md`）

每个镜头一行：

| # | 名称 | 起止(秒) | 景别/机位 | 画面内容 | 角色表演 | 特效 | 声音 |
|---|---|---|---|---|---|---|---|

另外写一段 CUES 表（全片的剧情节拍，单位秒），画面、特效、音乐都以它为准。分镜阶段就要定好每个场景用的 look（`k`、太阳高度和方位、雾、`shafts`），日式动画的情绪主要靠光和色来表达。

### 4.2 单镜头循环

```bash
cd anime-core
export STORY=<片名>
# 若使用外部 puppeteer-core 或指定浏览器，可额外设置 TOOLS_DIR 与 CHROME

npm run check                                     # 1 加载无报错
node tools/snap.mjs --scale 0.5 --sheet s07 s:<镜头名>@0.1 s:<镜头名>@0.5 s:<镜头名>@0.9   # → out/<片名>/snaps/
                                                  # 2 出镜头首、中、尾三张静帧，自己看图对照 §6 清单
node tools/snap.mjs "q:test=1&t=12&cam=5,3,8&at=0,1,0&fov=35=name:free"
                                                  # 3 自由机位：检查布景的背面/穿帮
node tools/turnaround.mjs --at x,y,z --facing 180 --height 2 --exprs open,happy --sheet <角色>
                                                  # 4 改了角色造型就出转面图 + 表情表（参数见 tools/turnaround.mjs 头部）
npm run determinism                               # 5 每完成一个场景跑一次
```

### 4.3 渲染

- 粗渲：`node tools/render.mjs --scale 0.5 --name rough`。软件渲染下全片大约要 15–25 分钟。
- 正式：`node tools/render-audio.mjs --name <片名> && node tools/render.mjs --name <片名> && node tools/build-player.mjs --video out/<片名>/<片名>.mp4 --out dist/<片名>.html --title <片名>`（默认 scale 2）。按约 2.4 秒/帧估算，70 秒约 70 分钟；镜头更复杂会更慢。
- 渲染按 48 帧一段，中断后重跑同一条命令即可续渲。**改了 `src/` 的任何文件，旧分段会自动作废**（源码哈希）。只改了某几个镜头、想保住其余分段时：删掉对应的 `out/<片名>/render/seg_XXXXX.*`（每部片各有一个目录），再加 `--reuse` 重跑。
- 整部片必须在同一台机器、同一种渲染后端上渲完，不同 GPU 或驱动渲出的像素会有细微差别。
- **GPU 提速工作流**（`tools/env.mjs`）：
  - 所有工具都认 `GPU=1`：Linux 下自动改用 `ANGLE=gl` 并补 `--enable-gpu`（WSL2 + NVIDIA 还要 `MESA_D3D12_DEFAULT_ADAPTER_NAME=NVIDIA`，否则会落到核显），单帧约 0.1–0.15 秒（比 CPU SwiftShader 快约 9.6 倍）。
  - 工具启动时打印 `webgl renderer: …`；`GPU=1` 却落回 SwiftShader / 核显时会打印 `!!!` 警告。
  - `render.mjs` 在分段元数据里记录渲染器：换了渲染器，旧分段自动重渲，不会把 CPU 段和 GPU 段混拼进一支成片（确实要混用时加 `--mixed`）。
  - **跨机器像素级回归基线**（旧片 `STORY=` 与 `STORY=_coretest` 的 `determinism.mjs` 固定哈希比对）保持默认 SwiftShader（不设 `GPU` / `ANGLE`）。

|---|---|---|

| **绘画天穹：多座积云塔、阴云、雨后一侧云开**（C2） | `skyDome({ towers: [cloudTower(rng, {...})] }, { rays, remnant, uniforms })` 挂在跟随相机的大球上并设 `ctx.sky`；每帧写 `uOvercast`（0 晴 → 1 漫天阴云）、`uAfterRain`、`uSideRays`、`uFlash`、`uCloudShift`。最多 24 座塔 × 64 团块（DataTexture）。**不要再用平面贴片拼云**（圆纸片叠边、海平线硬切） | core/clouds.js 文件头；示例 `films/_coretest/v3Test.js`（镜头 `stormSky`）、`films/cape-keeper/sky_storm.js` |
| **单侧平行斜光**（C1） | look 里 `shaftStyle: 'slanted'`（+ `shafts` 强度、`shaftAngle` 屏幕角°、`shaftBeams` 4–10、`shaftDown`）：低频宽光幕，只向太阳下游延伸，透光率读天穹写入的云遮光率。默认 `'radial'` = 旧放射条纹（太阳入画时会出 360° 车轮辐条，新片别用） | core/passes.js `ATMOS_FS`、core/look.js |

| **星空**（含淡银河，会闪烁，海面倒影里也有） | 调色板里写 `stars: 0..1`（随 k 插值），或 look 里直接给 `stars`；星色 `sky.star` | core/materials.js `skyMaterial` |

| 海面、倒影、接触泡沫 | 引擎自带的屏幕空间水面（`waterLevel`） | core/engine.js |

| 圆润的生物角色 | `SoftBody`：椭球 + 圆锥台平滑融合成一整张皮，自动蒙皮 | core/organic.js；完整示例 story/dino.js |

| **角色明暗：脸上只有一块阴影**（R1） | ① 明暗法线代理：SoftBody 用 `body.shadeProxy(bone, center, { r, k, rot })` + 材质 `shadeNormal: true`（代理跟着骨骼走，脖子处按蒙皮权重过渡）；刚体零件用 `celMaterial({ shadeProxy: { center, r, k } })`。② 单层阴影色 `celMaterial({ shade: '#屏幕色', shadeBase })`；花纹里不同色块的暗部在 pattern 里写 `gShade = cXxxShade;`（浅色块一定要给，否则按比例变暗会发紫）。③ 描线色 `celMaterial({ ink: '#屏幕色' })`（按 id 查表，同一 id 只能一种色）；`createEyes({ inkLine })`。④ `receiveShadow: false`：不接收角色投影（用了代理的脸要关，否则真实几何的自影会在脸上切出直线） | core/materials.js celMaterial 文件头；验收图 `out/coretest/r1_views.jpg`、`r1_sweep.jpg`（左旧右新） |

| **风：草浪、植物随风倒**（W1） | look 里写 `wind: { dir:[x,z], strength 0..1, phase }`（`phase` = 风力对时间的积分，米；故事层固定步长积分后缓存，强度变化时波不跳）。植物卡片顶部朝下风倒、波峰处倒得更多并亮一档（叶背）；地面 `paintMaterial({ windSheen: 1 })` 扫过同一个波场的硬边亮带。不写 `wind` 时逐像素不变 | core/glsl.js `windWave`、core/foliage.js、core/materials.js；用法见 `films/cape-keeper/weather.js` |
| **雨、远方雨幕与盔甲雨雾**（W8 / W9） | `core/rain.js`：`new RainField()` 加进 overlay，每帧 `update({ camera, t: onTwos(t), amount, shelter })`（`shelter = { x, y, z, rx, rz, rot }`：椭圆脚印内、高度 y 以下没有雨 —— 角色挡雨）；`new RainCurtain({ height, base, depth, color, cloud, foam, sea })` 每帧 `update({ t, amount, origin, dir, dist, lean })`（清晰的云底团块下沿 + 几层雨帘 + 前沿白海面线 + 雨下暗色海面带），雨墙推到眼前（`dist → 0`）时用 `RainCurtain.nearRain(dist)` 平滑交接给近处 `RainField`；`armorMist(water, glows, points, t, { amount, radius, wind, seed })` 在角色朝上的表面（头顶、肩甲、抬起的前臂）闭式弹出白水刺与薄雾 | 示例 `films/_coretest/rainWallTest.js`（镜头 `rainWall`）；长片用法见 `films/cape-keeper/fx.js` |

## 6. 自查清单（每个镜头出图后逐条检查）

- [ ] **构图**：主体在三分线或中心，地平线不切头，画面边缘没有穿帮（地形边缘、模型背面、天空接缝）。
- [ ] **可读性**：角色剪影清楚；脸朝镜头的镜头里能看清表情；背景比角色暗或者更灰。
- [ ] **光**：受光方向和 look 的太阳一致；逆光镜头有边缘光；不同镜头之间的光不乱跳（同一场景用同一套 look）。
- [ ] **颜色**：没有整块死黑或死白；没有饱和到发荧光的绿或蓝。
- [ ] **描线**：角色描线连续；同一个角色内部的色块交界处没有黑线；背景不描线。
- [ ] **动作**：一拍二；落地有压缩和回弹；尾巴、耳朵有随动；首尾帧能接上相邻镜头。
- [ ] **连贯**：相邻镜头的角色位置、朝向、光照、天气一致（越轴要有理由）。
- [ ] **加载与确定性**：`npm run check` 无报错；场景完成后 `npm run determinism` 显示 OK。

## 8. 常见坑与实战经验

- **逆光拍不清脸**：设定图和表情特写一律用正面打光（turnaround 默认就是）；正片里要看脸的镜头，用 look 的 `key` 把角色主光“作弊”到镜头这一侧。
- **大面积高光像面具**：圆润角色的 `gloss` 不超过 0.15。
- **SoftBody 链条上出现一圈圈条纹**：相邻圆锥台的融合系数 `k` 太大，降到 0.03 左右。
- **关节转超过约 60° 皮会塌**：手臂这类大幅运动的部位做成独立小零件，挂在关节上。
- **植物卡片是平面**：镜头不要贴着单张植物拍；近景用多层小草叠出层次，远景用大树。
- **镜头一多，时间容易错位**：所有时间都写成 `CUES.xxx + 偏移`，不要在镜头里硬写秒数。
- **URL 参数 `at=` 是自由机位的注视点**：部门自己的参数别叫 `at`（例如 `nagiAt`）。
- **重型分块机甲要点（来自《海岬的测风人》实战经验）**：
  1. **平地支膝坐姿挡脸与穿模**：厚重机甲直接坐平地会让双膝高耸挡死自己的镜头视线并与胸裙甲穿插；应安排高于地面约 2–2.5 m 的石台/基座抬高髋部，并将闲置手掌自然扶在石台侧沿（不压在膝盖顶上），腾空“眼睛 ↔ 地面小主体”的双向视线走廊。
  2. **大幅折腰遮挡机位**：守护地面小物体时，优先用“前臂与手掌平伸悬空成檐”替代大幅折腰伏身，既保持重机甲端庄剪影，又给仰拍机位留出充足通透空间。
  3. **动作节奏**：15–20 m 级巨型机械单次抬臂/收臂至少留 4.0–4.6 秒并配合五阶缓动（`core/util.js` 的 `easeHeavy` / `heavyAct`），切忌 1 秒级快速抽动。写完表演跑一次 `probe.mjs --check-cam / --check-sight / --collide`。
  4. **天穹与光束**：云一律画在 `core/clouds.js` 的 `skyDome` 里（平面贴片 `CloudBank` 已删除）；太阳会入画的镜头不要用默认的放射光束（`shaftStyle: 'radial'` 会出 360° 车轮辐条），改 `shaftStyle: 'slanted'` 或天穹自带的 `uSideRays` 侧光。
  5. **配乐“叮叮当”**：见上表 C7。前段克制、高潮拉开 10 dB 以上动态，用 `ffmpeg -af volumedetect` 分段量均值。
