# 02 渲染管线深度解析

> 对应原作文件：`src/engine.js`（pass 编排、描线、泛光、调色）、`src/passes-env.js`（笔触、水面、大气）、`src/glsl.js`（共享 uniform、MRT 协议）、`src/materials.js`（赛璐璐、overlay）、`src/bgmaterials.js`（背景/天空）、`src/look.js`（色彩脚本）。
> 对应 anime-core：`src/core/engine.js`、`passes.js`、`glsl.js`、`materials.js`、`look.js`。

## 2.1 总览：一帧是怎么画出来的

```
                  ┌──────────── 场景（scene）：所有 3D 物体，材质都走 writeOut()
                  │
 ① 阴影  ── 只渲染 shadowRoots（角色）到 4096² 深度图（uPass=1）
 ② 反射  ── 镜像相机渲染整个场景到半分辨率图（uPass=2，水面以下丢弃）
 ③ 主渲染 MRT ── textures[0] 颜色(a=是否背景)  textures[1] data=(视法线xy, 视深度, 材质id)
                  │
 ④ 笔触 PAINT  ── 只对 a=1 的像素（背景）做 8 扇区各向异性 Kuwahara → 水粉
 ⑤ 描线 INK    ── 只对 id∈[1,99] 的像素（赛璐璐）按 id/深度/法线找边 → 手绘线
 ⑥ 水面 WATER  ── 每个像素求视线与 y=水位平面交点，在那里“画”水（反射/透射/焦散/雨环/泡沫）
 ⑦ 大气 ATMOS  ── 距离雾（冷暖随太阳方向）、贴水薄雾、光束
 ⑧ 叠加 OVERLAY── 第二个 scene（雨丝、闪光、闪电、光束），无深度缓冲，读 data 图自己判断遮挡
 ⑨ 泛光 BLOOM  ── 亮度>1.05 才发光，1/4 与 1/8 分辨率两级模糊
 ⑩ 调色 FINAL  ── 超采样下采样、软肩、曝光/gamma、Vibrance、Lift/Gain、暗角、颗粒、淡入淡出
```

所有中间图都是 HalfFloat（允许 >1 的“过亮”值进泛光）。内部分辨率 = 输出 × `S`（成片 S=2）。

**设计哲学**：3D 只负责“形状、遮挡、透视”这些手绘最难的东西；“像画的”这件事完全交给后期 pass 按像素决定。所以换风格 ≈ 换后期，不用改模型。

## 2.2 MRT 协议：整个引擎的“宪法”

```glsl
// glsl.js —— 每个场景材质都必须调用它
layout(location = 0) out vec4 oColor;
layout(location = 1) out vec4 oData;
void writeOut(vec3 col, float a, vec3 nView, float viewDepth, float id){
  oColor = vec4(col, id > 0.5 ? 0.0 : 1.0);        // a 通道：1 = 绘画背景，0 = 赛璐璐
  oData  = vec4(nView.xy * 0.5 + 0.5, viewDepth, id);
}
```

| id 范围 | 含义 | 笔触 | 描线 |
|---|---|---|---|
| 0 | 绘画背景（建筑、地形、天空、植被、岩石） | ✔ | ✘ |
| 1–99 | 赛璐璐（角色、道具、画出来的水块） | ✘ | ✔ |
| 100+ | 赛璐璐但不描线（眼睛高光、玻璃反光、腮红、自带描边的特效） | ✘ | ✘ |

**为什么它这么重要**：后面 7 个 pass 全部只读这两张图做决策，彼此完全解耦。新增一种物体，只要选对 id，就自动获得正确的“画法”。

**id 的妙用 —— 让描线落在装甲接缝**：同一个角色的不同零件用不同 id（Sunshower 的 `Robot.part()` 自动循环 1..89），描线 pass 发现相邻像素 id 不同就画线 → 线正好落在零件分界。LEVIATHAN 更进一步：利维坦皮肤的**每一块鳞甲**都有自己的 id，所以每块鳞都被描一圈。

**id 的分配约定**（跨部门协调，写进 CONTRACT）：
- Sunshower：机器人 1–89，翠鸟和赛璐璐特效 90–99，100+ 不描线；FX 部门用 120/121。
- LEVIATHAN：赛璐璐特效 60–99，水特效 80–99，100+ 不描线；“ids wrap, keep neighbours different”。

**uPass 约定**（每个材质都要处理）：
```glsl
if(uPass > 1.5 && vWorld.y < uWaterLevel - 0.03) discard;            // 反射 pass：丢掉水下部分
if(uPass > 0.5 && uPass < 1.5){ oColor = vec4(1); oData = vec4(0); return; }  // 阴影 pass：只要深度
```

## 2.3 角色：赛璐璐材质（`celMaterial`）

核心光照只有十几行，却决定了“动画感”：

```glsl
float ndl = dot(N, uKeyDir);                               // 注意：用的是“主光”而不是太阳
float lit = smoothstep(-0.03, 0.05, ndl) * sunShadow(vWorld, N);   // 极窄的过渡 = 硬分界
vec3 litCol   = col * mix(uSkyTint, uSunColor * 1.06, uSunStrength);
float up      = smoothstep(-0.7, 0.6, N.y);
vec3 shadeCol = col * uShadeTint * mix(uBounce, vec3(1.0), up);   // 暗部：冷薰衣草色 × 朝下面吃反弹光
vec3 outc = mix(mix(shadeCol, litCol, 0.12), litCol, lit);
float deep = step(ndl, -0.55) * step(N.y, -0.35);           // 第三色：只在背光且朝下的面
outc = mix(outc, col * uDeepTint, deep * 0.85);
float spec = step(0.985 - wet * 0.03, dot(N, H)) * lit * uGloss;    // 阶跃高光（一块，不是渐变）
float rimL = smoothstep(0.68, 0.72, fres) * ... * back * uSunStrength; // 逆光时的边缘光
```

要点：

1. **两个硬色阶**：`smoothstep(-0.03, 0.05, ndl)` 几乎是阶跃函数。这是赛璐璐“影”的画法。
2. **暗部永远是彩色的**：`uShadeTint = #a6b1e2`（薰衣草蓝）。CONTRACT 原话：“cool lavender-blue cel shadows, never muddy or grey”。
3. **主光作弊（key light cheat）**：`uKeyDir` 与 `uSunDir` 分离。Sunshower 里太阳在机器人**背后**（为了雨丝逆光闪亮、边缘光），但角色主光从**前右上方**打（`st.key = [0.5, 0.62, -0.6]`），所以脸永远不会沉在阴影里。这是动画的标准“画法”，不是物理。
4. **阴影只来自角色**：阴影 pass 只渲染 `shadowRoots`（机器人和翠鸟），“so set dressing never drops a building's shadow across the robot — painted lighting, not physics”。翠鸟能在机器人手指上投出影子，是因为阴影相机紧贴角色、depth 很小（bias 小）。
5. **风化“粘”在装甲上**：污渍/掉漆/锈迹/水线藻类全部由噪声计算，输入是 `aRest`（机器人在“静止姿态”下每个顶点的世界坐标，`bakeRest()` 预烘焙进顶点属性）。所以手臂怎么动，污渍都不会游走。污渍都是 `step()` 硬边、偏紫、暗一档 —— 像画师画的“污渍色块”，不是 PBR 的脏。
6. **玻璃只画反光**：面罩玻璃 id=150、贴图只有反光条纹，“only its reflections are drawn (anime convention), so the camera unit stays visible with real depth behind it”。

LEVIATHAN 的弓兵把它升级为**“动画式镀铬”**（`archer-mat.js`）：反射向量 `R.y` 落在哪个区间就取哪一档颜色 —— 深空 / 蓝天 / 白云 / 地平线高光 / **一条硬的深色地平线** / 海 / 地面反光。机甲画师画银色金属就是这样画的：硬色带，不是平滑的环境贴图。

```glsl
vec3 chromeEnv(vec3 R, vec3 p){
  float e = R.y + (vnoise3(p * 1.3 + 4.0) - 0.5) * 0.22;   // 色带边缘轻微抖动
  if(e > 0.72) return vec3(0.56, 0.72, 0.98);   // 深空
  if(e > 0.36) return vec3(0.78, 0.88, 1.03);   // 蓝天
  if(e > 0.12) return vec3(0.97, 0.98, 0.99);   // 云白
  if(e > 0.02) return vec3(1.06, 1.03, 0.96);   // 地平线高光
  if(e > -0.10) return vec3(0.40, 0.46, 0.66);  // 硬的暗地平线 —— 镀铬感的关键
  if(e > -0.42) return vec3(0.34, 0.56, 0.76);  // 海
  return vec3(0.74, 0.70, 0.66);                // 地面反光
}
```

## 2.4 背景：绘画材质 + Kuwahara 笔触

**材质层**（`bgmaterials.js` 的 `PAINT_LIGHT`）：柔和明暗交界 `smoothstep(-0.03, 0.15, ndl)`、薰衣草环境光、贴水的松石绿反弹光（`exp(-高度/7)`）、受光面只到 0.46 × 太阳色（“high-key: sunlit planes land just under white instead of clipping”）。

Sunshower 的整座城市**只有一个材质**（`cityMaterial`）：所有建筑/甲板/招牌把参数塞进顶点属性（`aCol/aCol2/aP/aQ/aR`：类型、种子、楼层高、窗户样式、苔藓、假投影、AO、湿带……），所以整座城合并成几个 draw call。窗户、阳台、卷帘门、瓦片全部在片元着色器里按 uv（米）画。

**笔触层**（`PAINT_FS`）：广义各向异性 Kuwahara。

```
对每个背景像素：
  1. 取一个缓慢旋转的“笔触方向场”（fbm 噪声） → 椭圆笔刷方向 dA、dB
  2. 半径按深度缩小（10 m → 120 m 从 0.72 降到 0.4）：远处的窗户和招牌保持可读
  3. 3 个半径 × 16 个方向采样，分到 8 个重叠扇区，算每个扇区的均值与方差
  4. 权重 = 1 / (1 + (std × 22)^8) —— 越平坦的扇区权重越大
  5. 加权平均 → 平坦区变成笔触色块，边缘与小细节被保留
  6. 叠加干笔刷纹（沿笔触方向拉长的噪声）和纸纹
```

关键细节：采样时 `tc = t.rgb * t.a` —— **赛璐璐像素 a=0，不参与平均**，所以角色的颜色不会“晕”进背景，背景的笔触也不会跨过角色轮廓。

## 2.5 描线（`INK_FS`）

```glsl
bool inked(float id){ return id > 0.5 && id < 99.5; }
// 8 个方向采 data 图，三类边：
if(abs(dN.a - dC.a) > 0.5){                        // ① 材质 id 不同
  if(cC && cN) ee = 1.0;                           //    两边都是赛璐璐：画
  else if(cC) ee = (dC.b < dN.b + 0.5) ? 1.0 : 0.0;//    赛璐璐对背景：只有赛璐璐在前面才画（外轮廓）
} else {
  float rel = abs(dN.b - dC.b) / max(min(dN.b, dC.b), 0.01);
  ee = smoothstep(0.015, 0.035, rel);              // ② 相对深度跳变（自遮挡轮廓）
  ee = max(ee, smoothstep(0.78, 0.6, dot(nC, nrm(dN))) * 0.85);  // ③ 法线折角（硬边）
}
// 线宽 = 基础宽 × 笔压噪声(屏幕空间, 随“原画”换种子) × 距离衰减
float press = 0.72 + 0.56 * vnoise(fc / 34.0 + uSeed * 7.0);
float dist  = clamp(14.0 / max(dC.b, 0.1), 0.5, 1.25);
// 两种宽度各算一次取平均 → 线条有粗细起伏
float e = 0.5 * edgeAt(vUv, dC, nC, w) + 0.5 * edgeAt(vUv, dC, nC, w * 0.55);
vec3 ink = mix(uInk, col.rgb * 0.32, 0.25);       // 墨色带一点底色（不是死黑）
```

`uSeed = floor(t × 12) % 5` —— 笔压噪声每张“原画”换一次，线条会像手绘一样轻微“呼吸”，但不会每帧乱抖。

**镜头可调线宽**：LEVIATHAN 每个镜头可设 `inkWidth`（远景巨物用 1.6–1.8），因为 900 m 的怪兽在画面里要“读得出”轮廓。

## 2.6 屏幕空间水面（`WATER_FS`）

不建水面网格。对每个像素：

```glsl
vec3 wdir = 视线方向;  float t = (uWaterLevel - uCamPos.y) / wdir.y;   // 与水平面的交点
if(sceneVD < 8000.0 && waterVD > sceneVD) 保持原色;                   // 水面前面有东西
P = 交点; q = P.xz;   // 后面全部用世界坐标 q 计算
```

Sunshower 版本按顺序做了：

| 层 | 做法 |
|---|---|
| 法线 | fbm 高度场 + 12 个“涟漪槽位”（`uRip/uRipB`：圆心、起始时间、振幅、速度、宽度、衰减、泡沫）+ 机器人涉水尾迹（Kelvin 波臂） |
| 雨环 | 网格单元里每个“雨滴”周期性落下，画 SDF 圆环线，**线宽按像素足迹保证 ≥1 px**；远处退化成细碎闪烁 |
| 反射 | 镜像相机图 + 法线扰动 + **竖直方向 7 次采样涂抹**（动画里倒影的画法）+ **反射亮度 7 级色阶化 30%**（赛璐璐分层感） |
| 透射 | 用场景深度重建水下点，按折射角算光程，吸收成深色；街道、斑马线、沉没的车在清水里可见 |
| 焦散 | 两层 Voronoi 边“光网”，域扭曲、粗细变化、交点更亮；用角色阴影图遮挡（机器人的腿下没有焦散） |
| 小鱼 | 4 群鱼的 SDF 剪影 + 它们投在街道上的影子 |
| 太阳 | 柔光 + **一颗颗分开的闪点**（每个网格单元一颗，按法线判断是否反射太阳，每几张原画重掷）——“never one blown disc” |
| 水纹短线 | 相机对齐的拉伸噪声取阈值 → 画出来的横向短线 |
| 泡沫 | **接触泡沫**：任何刺穿水面的物体，`under`（水下距离）很小处自动出一圈白沫 —— 不用美术摆放 |

LEVIATHAN 在同一个 pass 里加了 `oceanColor()`（`world-ocean-glsl.js`）：千米尺度的开放海洋。**涌浪是“着色”出来的不是位移出来的**：6 组带尖峰的 swell train（波长 520 m → 6 m），**小于像素足迹的波段自动淡出**（防闪烁）；五档硬色调；三个尺度的手绘白浪（新月形、随一拍三生长撕裂、带吹散的泡沫尾）；船的尾迹（中央翻滚白沫 + Kelvin 波臂）；巨兽在海下的阴影。

> anime-core 里的 `WATER_FS` 是精简版（法线、涟漪、反射、透射吸收、闪点、水纹、接触泡沫），并修复了一个精简时引入的 NaN 问题（见 2.11）。

## 2.7 大气（`ATMOS_FS`）

- **距离雾**：颜色在 `uFogCool` 与 `uFogWarm` 之间按“视线与太阳夹角”插值 —— 朝太阳方向暖、背对冷。
- **贴水薄雾**：`uMist × exp(-高度/uMistHeight) × fbm 雾堤`，远处才出现。
- **天空像素的地平线雾**：`exp(-wdir.y × 18)`。
- **雨幕**（Sunshower）：雨越大雾越浓，且朝太阳方向更亮（逆光水滴）。
- **光束**：从像素朝太阳的屏幕位置步进 28 次，统计“是天空的像素”的比例（画面上方之外也算天空），再乘一个随角度变化的条纹噪声。
- **海天融化**（LEVIATHAN）：远海和天空在地平线处用同一种“天空自己的地平线色”融合，避免硬接缝。

## 2.8 叠加层（overlay）

第二个 `THREE.Scene`，在水面和大气**之后**、用同一个相机渲染，**没有深度缓冲**。材质读 `uSceneData`（主渲染的 data 图）自己判断遮挡：

```glsl
float sceneD = texture(uSceneData, gl_FragCoord.xy / uRes).b;
float soft = clamp((sceneD - vDepth) / uSoft, 0.0, 1.0);   // 软深度：靠近物体时渐隐
```

为什么要放在水面/大气之后：雨丝、闪光、光束本身就是“光”，不应该被雾冲淡、不应该出现在水面倒影里。

LEVIATHAN 的能量部门把遮挡做成了**三种模式**（`fx-energy-core.js`）：
- mode 0：深度测试（带容差 bias）
- mode 1：**只在比 bias 更近的几何体上画**（电流“爬”在装甲和皮肤上）
- mode 2：不测试

> **坑**：水面是屏幕空间画的，不在 data 图里。水面附近的特效如果做深度测试，会被**水下的海床**挡掉，出现一条笔直的硬边。我在 anime-core 里实际踩到了这个坑（入水闪光被切掉下半截），解决办法是给每个精灵/线条一个遮挡模式（0 全测 / 1 只被角色挡 / 2 不测），见 `anime-core/src/core/materials.js` 的 `OCCLUDE`。

## 2.9 泛光与调色

**泛光**：阈值 1.05（`smoothstep(1.05, 1.45, max(r,g,b))`）—— 只有“过亮”的东西才发光。所以自发光材质要输出 >1 的颜色（眼睛 `uEmissive × (1 + 2.5 × eyes)`，信标 `× (1.2 + 3 × sweep + 2 × core)`）。两级：1/4 分辨率两遍、1/8 分辨率四遍。

**调色（FINAL_FS）**，顺序很讲究：

```glsl
c += bloom * uBloom;
c = c / (1.0 + max(c - 1.0, 0.0) * 0.6);   // 软肩：只压 >1 的部分
c *= uExposure;                             // 1.12
c = pow(max(c, 0.0), vec3(uGamma));         // 0.84：打开中间调（high-key）
float chroma = max3(c) - min3(c);
c = mix(vec3(l), c, uSat * (1.0 + uVibrance * (1.0 - chroma)));  // Vibrance：只给低饱和区加饱和
c = uLift + c * (uGain - uLift);            // 黑位抬到 #161c2e（带蓝的暗）、白位 #fffdf8（暖白）
c *= 1.0 - uVignette * dot(q, q) * 1.6;     // 暗角
c += (hash(gl_FragCoord.xy + uFrame*17.31) - 0.5) * uGrain;   // 逐帧颗粒
c = mix(c, uFadeColor, uFade);              // 淡入淡出（Sunshower 淡到暖白 #fffaf0）
```

“高调”是客户的硬要求：“BRIGHT, luminous… no murky or muddy darks. The final grade already lifts exposure.” LEVIATHAN 的原参考片是阴郁写实的，他们**刻意**改成“烈日晴空、钴蓝到松石绿的海、白云带薰衣草阴影面”，“Drama comes from scale and contrast, never from murk.”

## 2.10 色彩脚本：一个 `k` 控制全片（`look.js`）

```js
export const PRESETS = {
  shower: { sunColor, sunStrength: 0.74, shadeTint, sky: {...}, fog: {...}, water: {...}, grade: {...} },
  summer: { sunColor, sunStrength: 1.0,  shadeTint, sky: {...}, fog: {...}, water: {...}, grade: {...} },
};
// 每个镜头只给 look = { k, sunElev, sunAz, shafts, ... }，applyLook 把 ~30 个颜色一起在两套预设之间插值
mixC(G.uShadeTint.value, A.shadeTint, B.shadeTint, k);
mixC(sky.uZenith.value, A.sky.zenith, B.sky.zenith, k);
mixC(atmos.uFogWarm.value, A.fog.warm, B.fog.warm, k);
mixC(water.uDeep.value, A.water.deep, B.water.deep, k);
mixC(final.uLift.value, A.grade.lift, B.grade.lift, k); ...
```

Sunshower 的天气脚本：`k = 1 - 0.45 × veil`（薄云遮日的程度），雨、彩虹另有曲线。**一个数字联动天空、雾、水、角色暗部、调色** —— 永远不会出现“天阴了但水还是晴天色”。这是给 AI 写镜头时最友好的接口：镜头只需要说 `k: 0.6`。

LEVIATHAN 把 `look` 扩展成每个镜头一个函数（`LOOKS.s15 = () => ({ k, sunElev, sunAz, key, shadow:{center,radius,depth}, inkWidth, paintRadius, water, fogMul... })`），由拥有该镜头的部门填写。

## 2.11 颜色空间陷阱（重要，原作文档没写）

three.js r170 默认 `THREE.ColorManagement.enabled = true`：`new THREE.Color('#1c5ed2')` 会把 sRGB hex **转换成线性值**存起来。而这条管线 `renderer.outputColorSpace = LinearSRGBColorSpace`，**最后不做 sRGB 编码**，只靠 FINAL_FS 的 `gamma 0.84 × exposure 1.12` 提亮。

后果：**look.js 里写的 hex ≠ 屏幕上的颜色**（屏幕上更深、更艳）。原作所有调色板都是在这个前提下“调出来”的。LEVIATHAN 的水特效部门显然注意到了这点，专门写了 `palValues()` 绕开 `THREE.Color`，注释写着 “the colours above are authored directly in display space”。

我在 anime-core 里试过关掉 ColorManagement（让 hex 即所见），结果整片发灰发白 —— 因为照搬过来的调色板和 grade 都是按“被线性化”调的。最后恢复默认并加了注释。**结论：要么保持原作的约定，要么关掉后整体重调调色板和 grade，二者不能混用。** 同一部片子里所有部门必须用同一种约定。

> 另一个我实际踩到的坑：精简水面 pass 时，天空像素在地平线附近 `waterVD > sceneVD`，“水下距离”变成巨大负数，`exp()` 溢出成 ∞，`-∞ × 0 = NaN`，再被泛光模糊扩散成**黑色方块带**。原作用 `min(depthB/cosR, under)`（depthB ≥ 0）天然避免了。教训：后期 pass 里所有 `exp()` 的参数都要夹紧。
