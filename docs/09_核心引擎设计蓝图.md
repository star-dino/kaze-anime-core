# 09 核心引擎设计蓝图：换故事，不改引擎

目标：做一个“日式动画核心引擎”，让你（和 AI 团队）以后做新故事时**只写故事，不碰引擎**。本章给出分层架构、接口规范、原作问题清单、移植优先级和路线图。`anime-core/` 是这份蓝图的第一版实现（P0 已完成并验证）。

## 9.1 设计目标

| 目标 | 衡量标准 |
|---|---|
| 故事无关 | 新故事 = 新建 `src/story/<名字>/`，`core/` 零修改 |
| AI 友好 | 故事用“人能读懂的数据 + 小函数”描述（CUES、镜头表、原画表、look 预设）；所有约束写进合同和 lint |
| 可复现 | 同一源码 → 逐像素相同的成片（`tools/determinism.mjs` 自动验证） |
| 可并行 | 部门独立加载、文件所有权、锚点 API |
| 风格可换 | 风格 = look 预设 + pass 参数 + 材质参数；新增风格不需要改故事 |
| 可交付 | 一条命令 → MP4 + 单文件 HTML |

## 9.2 分层架构

```
L5 制作层   CONTRACT.md / 开工清单 / 部门提示词模板 / 审片流程（静帧 + 频谱图）
L4 内容层   src/story/<故事>/   story.js（CUES, SHOTS, look, state, departments）+ 各部门模块
──────────────────────────────── 故事与引擎的边界 ────────────────────────────────
L3 导演层   core/film.js        createTimeline(story)：evalFrame → st；镜头连续性校验
            core/runtime.js     boot(story)：部门容错加载、URL 调试参数、window.FILM API
L2 资产层   core/kit.js         hull / cbox / superPts / blob / spike / Rig / anchors / solve2
            core/fx.js          GlowBatch / LineBatch / Ripples / boltPts（无状态特效批次）
            core/materials.js   cel / paint / sky / glow / line（含遮挡模式、深色外缘）
L1 渲染层   core/engine.js      10 个 pass 的编排
            core/passes.js      笔触 / 描线 / 水面 / 大气 / 泛光 / 调色 着色器
            core/glsl.js        共享 uniform G、MRT 协议 writeOut、噪声库
            core/look.js        色彩脚本（预设插值）
L0 工具层   tools/              check / snap / determinism / render / render-audio / build-player
            src/audio/          DSP 工具箱 + 配乐/音效 + 离线渲染
```

依赖方向只能向下。L4 可以 import 任何下层；L1–L3 **永远不 import** `story/`（runtime 通过参数拿到 story 对象）。

## 9.3 故事接口规范（story schema）

```ts
interface Story {
  title: string; fps?: number /*24*/; duration: number; width?: 1920; height?: 1040;
  cues: Record<string, number | [number, number]>;          // 全片唯一时间真相
  shots: Shot[];                                             // 首尾相接（film.js 会校验）
  look?: Look;                                               // 默认 look，镜头可覆盖
  presets?: { [name: string]: Palette };                     // 两套调色板，k 在其间插值
  state?(st: State): void;                                   // 故事专属状态：淡入淡出、天气、情绪曲线…
  departments: { name: string; load: () => Promise<Module>; factory: string }[];
}
interface Shot { name: string; start: number; end: number;
  cam(lt: number, d: number, t: number, st: State): { pos: V3; look: V3; fov: number; roll?: number; near?: number; far?: number };
  look?(lt, d, t, st): Partial<Look>; }
interface Look { k: number; sunElev: number; sunAz: number; key?: V3; shafts?: number; water?: boolean; waterLevel?: number;
  fogMul?: number; mistMul?: number; paintRadius?: number; inkWidth?: number; shadow?: { center: V3; radius: number; depth?: number }; cloudDrift?: number; }
// 部门：factory(ctx) → { update(st) , ...对外 API }；update 必须是 st 的纯函数
interface Ctx { THREE; scene; overlay; engine; camera; G; CUES; SHOTS; FPS; shadowRoots: Object3D[]; sky?: Mesh; story; [dept: string]: any }
```

## 9.4 引擎必须“强制”的规则（而不只是写在文档里）

| 规则 | 原作 | anime-core |
|---|---|---|
| 纯函数时间 | 约定（CONTRACT） | `tools/determinism.mjs`：静态扫描 `Math.random/Date.now` + 乱序/新会话逐像素比对 ✔ |
| 镜头首尾相接 | 无 | `film.js` 加载时校验并警告 ✔ |
| 部门崩溃不拖累全片 | `dept()` 回退 NOOP | 同 ✔ |
| 加载报错不渲染 | render.mjs ✔ | render.mjs ✔ |
| 颜色空间约定统一 | 隐含，未写明 | runtime.js 注释写明；建议加入 CONTRACT ✔ |
| 后期 pass 无 NaN | 原作写法天然安全 | 修复了精简版引入的 NaN，规则：所有 `exp()` 参数夹紧 ✔ |
| 字体随项目分发 | 依赖 Windows 字体 | 待做（P1） |
| 描线 id 段落 | 写在 CONTRACT | 建议在 core 里提供 `idRange('dino')` 分配器（P1） |

## 9.5 原作问题清单（审读发现）

| # | 问题 | 位置 | 影响 | 建议 |
|---|---|---|---|---|
| 1 | `Math.random()` 用于苔藓色相 | Sunshower `robot.js:320` | 每次页面加载颜色不同；崩溃重启后渲染的段可能对不上 | determinism 测试 + lint |
| 2 | hex 颜色被 three 线性化，管线不编码 | 两部片的 `look.js` 等 | 写的颜色 ≠ 看到的颜色；部门间约定不一致（splash 部门绕开了） | 明确写进合同；或全局关掉并重调 |
| 3 | 日文用系统字体 `Yu Gothic/Meiryo/MS Gothic` | Sunshower `textures.js:176` | 换机器字形变化 | 字体文件随项目分发 / 烘成路径 |
| 4 | Chrome `--use-angle=d3d11`、频谱字体 `C:/Windows/Fonts/arial.ttf` | `tools/env.mjs`、`render-audio.mjs` | Linux/macOS 跑不起来 | 平台判断（anime-core 已做 ANGLE 选择） |
| 5 | 引擎代码按部门复制而非共享 | 两个仓库 | 修一个 bug 要改两处 | 抽成 `core/`（即 anime-core） |
| 6 | 部门列表、URL 调试参数写死在 `main.js` | `main.js` | 换故事要改引擎入口 | `story.departments` 声明式加载（anime-core 已做） |
| 7 | `setupShadow` 里构造了未使用的 bias 矩阵 | `engine.js` | 无害 | 清理 |
| 8 | LEVIATHAN `index.html` 标题仍为 “Sunken Patrol — workbench” | `index.html` | 无害，复制粘贴痕迹 | 标题从 story 读取 |
| 9 | 只有两套预设的 `k` 插值 | `look.js` | 夕阳/夜景/雨夜需要更多色彩状态 | 扩展为“多关键色板 + 时间轴插值” |

## 9.6 移植优先级（从原作搬什么到 core）

**P0 —— 已在 anime-core 实现并验证**
- 10-pass 渲染（阴影、反射、MRT、Kuwahara、描线、屏幕空间水面精简版、大气、overlay、泛光、调色）
- cel / paint / sky / glow / line 材质（含遮挡模式、亮背景深色外缘）
- 色彩脚本 `look.js`；导演层 `film.js`；运行时 `runtime.js`
- 建模 kit（凸包、超椭球、尖刺、关节树、锚点、两骨 IK）
- 无状态特效批次（发光、线条、闪电、涟漪槽）
- 程序化音频核心（总线、SVF、噪声、模态、PolyBLEP pad、卷积混响、WAV）
- 工具链（check / snap / determinism / render / render-audio / build-player）
- **有机建模层**（2026-11-05 补，来自 Sunshower 翠鸟，见 04 §4.8）：
  - `SoftBody`：SDF 平滑并集，Surface Nets 网格化；
  - `Skin`：按距离自动算多骨骼权重，CPU 线性混合蒙皮；
  - `celMaterial` 的 `pattern / rest` 选项：静止坐标花纹，不受光的标记色；
  - `face.js`：画出来的眼睛、眼神朝镜头、表情笔画；
  - `starPlate`、`color.js` 的屏幕色换算、`turnaround.mjs` 设定图工具

**P1 —— 下一步最值得移植（大部分能直接从 Sunshower 搬，MIT）**
1. `textures.js`：手写字骨架 + 笔刷描边 + 手绘粗糙化；面板缝 → `core/paint2d.js`
2. `celMaterial` 的投影贴花（`det` 两张）与 `bakeRest`（aRest 风化）
3. `tex-foliage.js` + `foliageMaterial`：画出来的树丛图集（直接通用）
4. 完整水面（焦散、雨环场、Kelvin 尾迹）与雨幕（`fx-rain.js`）
5. `tempoMap`（速度图锚定 CUES）、LUFS 归一 + 前视限幅（`audio-dsp.js` 的 `lufs/limit`）
6. 音频空间探测（锚点 → 声像）
7. render.mjs 的源码哈希、多段重试、孤儿进程回收
8. `SpriteBatch / RibbonBatch`（水滴、水流）
9. 字体随项目分发；描线 id 分配器

**P2 —— 大场景/巨物/机甲（来自 LEVIATHAN）**
1. `lev-spine.js`（GPU 脊柱）+ 放样建模 + 曲线原画（`vecCurve` + 弧长铺设 + 弹道重心）→ 龙、蛇、鲸、触手
2. `PuffBatch`（写深度的冒名顶替水团）+ 射流发射器 → 大水、云、烟、爆炸
3. `world-ocean-glsl.js`（千米海洋、白浪、尾迹）
4. `archer-mat.js` 动画式镀铬 + `archer-geo.js` 的 Kit 合并 + 面板图集 → 机甲
5. `world-planet.js`（光追星球）、`fx-energy-sky.js`（撕裂云层）
6. 按部门的镜头/look 注册表（`registerCams`）+ 按场景默认机位

**P3 —— 风格扩展（新功能）**
- 多套风格预设：`summer-gouache`（现有）、`golden-hour`、`night-city`、`rainy-blue`、`showa-cel`（限色 + 片门晃动 + 更粗颗粒）
- 可选 pass：色差、光晕（halation）、镜头光斑、片门晃动、手绘“抖线”（boiling lines）
- 2D 层：在 3D 之上合成手绘风格的 UI 字幕、片名、分镜框

## 9.7 “风格”应该放在哪里

| 风格维度 | 放在哪 | 例子 |
|---|---|---|
| 色彩 | `look` 预设（调色板 + grade） | 盛夏 / 黄昏 / 雨夜 |
| 笔触强度 | `look.paintRadius`、PAINT_FS 常数 | 吉卜力水粉（4）/ 更厚涂（8–14） |
| 线条 | `look.inkWidth`、`uInk` 墨色、笔压噪声 | 细线（1.0）/ 剧场版粗线（1.6–1.8） |
| 赛璐璐阶数 | celMaterial 的阈值、是否启用第三色 | 两阶 / 三阶 |
| 拍数 | `onTwos/onThrees` 的使用 | 剧场版（一拍二）/ 低成本 TV（一拍三）|
| 特效画法 | 特效材质（白芯 + 色带 + 深色外缘） | 新海式柔光 / 金田系硬边 |
| 颗粒、暗角 | FINAL_FS 参数 | 胶片感强弱 |

这样，**同一个故事可以一键换风格**，同一个风格可以服务所有故事。

## 9.8 让 AI 更好写故事的辅助（建议加入 core）

1. **镜头语言助手**：`dolly(from, to, ease)`、`orbit(center, r, a0, a1)`、`push(target, dist0, dist1)`、`handheld(amp, freq)`、`shake(t0, amp, decay)` —— AI 写镜头时直接组合。
2. **表演表助手**：`actingSheet([[t, '原画名'], ...], DRAW, { breakdown: 0.62, onTwos: true })` 返回当前姿态 —— 把翠鸟那套通用化。
3. **锚点注册表**：每个角色导出 `ANCHORS = ['head', 'mouth', ...]`，工具能自动生成锚点清单写进合同。
4. **合同生成器**：从 `story.js` 自动生成 CONTRACT 的镜头表、CUES 表、部门所有权表。
5. **审片联系表**：一条命令出“每个镜头首/中/尾 3 张”的总览图。
6. **性能报告**：每个镜头的平均 ms/帧，提示超预算的镜头。

## 9.10 《海岬的测风人》（`cape-keeper`）长片实战下沉的能力（2026-11-07 已合入）

100 秒 / 15 镜重型机甲短片《海岬的测风人》（`src/films/cape-keeper/`）先在故事层验证、再下沉进内核的 7 项能力。全部是可选项：不用时旧片逐像素 / 逐采样不变（示例片第 151 帧仍是 `77d7bd9f9f92`）。最小示例在 `src/films/_coretest/v3Test.js`（镜头 `stormSky`、`motionArc`），用法表见 11 号文档 §5。

1. **单侧斜射光束（`core/passes.js` `ATMOS_FS`）**：look 的 `shaftStyle: 'slanted'` —— 低频宽光幕（频率 4–10，替代极角 × 30/80 的高频噪声），只向太阳下游延伸，透光率按天穹写进 data.r 的云遮光率调制。默认 `'radial'` 保持旧行为。
2. **绘画天穹（`core/clouds.js` `skyDome` / `cloudTower`）**：24 塔 × 64 团块的 `RGBA32F DataTexture` 并集积云（包围盒早退、`fwidth` 抗锯齿、三阶明暗、逆光银边）+ 卷云丝 + `uOvercast` 连续水粉阴云 + 雨后一侧残云与 `uSideRays` 侧光。平面贴片 `CloudBank` 已删除。旧的 `skyMaterial(puffs)` 原样保留。
3. **旋转残影 `MotionArcBatch`（`core/fx.js` + `materials.js` `motionArcMaterial`）**：overlay 层、预乘 alpha、读 `uSceneData` 软遮挡的无状态扇形残影；`blur()` 按角速度自动淡入，通用于风杯、螺旋桨、风扇、车轮。
4. **重型机甲工具（`core/util.js`、`core/kit.js`、`tools/probe.mjs`）**：`easeHeavy` / `heavyAct`（预备 + 液压落位）；`Rig.addCollider` + `checkSelfCollision`（球 / 胶囊自穿插体检）；`probe.mjs --check-cam / --check-sight / --collide` 全片巡检，按零件名报告遮挡。
5. **命名权重调色与柔边淡变（`core/look.js`、`core/passes.js`）**：look 的 `presetWeights` 按权重直接混合任意几套调色板；`st.fadeSoft` 四角先收、中心最后收的胶片式淡变。
6. **显式 GPU 开关（`tools/env.mjs`、`tools/render.mjs`）**：`GPU=1` 走 `ANGLE=gl` + `--enable-gpu`，所有工具打印 `UNMASKED_RENDERER_WEBGL` 并在落回软件渲染 / 核显时告警；分段元数据记录渲染器，防止 CPU / GPU 分段混拼。默认仍是 SwiftShader（守护基线）。
7. **温暖声部与自然拟音（`src/audio/dsp.js`）**：`sing`、`celloHorn`、`warmHarp`、`warmTimpani`、`airSwell`、`softDrop` 成为标准导出；`ping()` 增加可选 `{ attackMs, maxHz, lpCut, lpDecay }`。

## 9.12 第三批下沉（2026-11-07）：水面雨环、地面水洼、雨墙交接、盔甲雨雾与纯 JS 混响

全部可选、不用时旧片逐像素 / 逐采样不变：

- **水面雨环与地面水洼**（`core/glsl.js` `RAIN_RING_GLSL` / `PUDDLE_GLSL`、`core/passes.js` `WATER_FS`、`core/materials.js` `paintMaterial({ puddles: true })`、`core/look.js` `rainRings` / `puddles`）：无状态 3×3 邻格哈希的一拍三赛璐璐雨环（第 1 张溅点 + 断续小冠，后 5 张外扩亮环 + 内侧暗环，远处自动退化为一拍三闪烁白点），海面与水洼共用；地面水洼在平地凹处积水，倒映三档天色、云影、太阳高光点与远边亮水沿（示例：`src/films/_coretest/rainWaterTest.js`，镜头 `rainWater`）。
- **远方雨幕升级与盔甲雨雾**（`core/rain.js` `RainCurtain`、`armorMist`）：`RainCurtain` 升级为单网格多层雨帘 + 团块并集水彩积色云底下沿 + 脚下白浪线 + 雨下暗色海面带，并提供 `RainCurtain.nearRain(dist)` 在 `dist → 0` 时与近处 `RainField` 无缝交接；`armorMist(water, glows, points, t, opts)` 在角色朝上表面闭式弹出白水刺与薄雾（示例：`src/films/_coretest/rainWallTest.js`，镜头 `rainWall`）。
- **跨平台确定性纯 JS 混响**（`src/audio/dsp.js` `makeIRData` / `convolveStereo`、`src/audio/soundtrack.js`）：可选 `story.audio = { reverb: 'js' }`（或 `?reverb=js` / `render-audio.mjs --reverb js`），用双精度基 2 FFT 分块重叠相加取代浏览器原生 `ConvolverNode`，保证跨浏览器 / 跨系统 100% 逐位一致（与 WebAudio 混响的 PSNR ≈ 124 dB）。
