# 07 工具链与交付

> 对应原作：`tools/env.mjs`、`snap.mjs`、`check.mjs`、`probe.mjs`、`sheet.mjs`、`render.mjs`、`render-audio.mjs`、`build-player.mjs`、`player/player.html`、`player/test-player.mjs`、`index.html`、`audio.html`。
> 对应 anime-core：`tools/*`、`player/player.html`、`index.html`、`audio.html`（精简版，已在 Linux 验证）。

## 7.1 影片页 = 一个带 API 的网页

`index.html` 既是**人用的工作台**（时间轴拖动、←→ 单帧、Shift 跳 1 秒、空格播放），也是**工具用的渲染服务**。`main.js` 暴露：

```js
window.FILM = {
  FPS, FRAMES, CUES, SHOTS, ctx,
  renderFrame(n) { renderState(stateFor(n)); return true; },   // 画任意一帧
  capture(q = 0.93) { return canvas.toDataURL('image/jpeg', q); },
  stateFor,                                                     // 只算状态不画（音频探测用）
};
window.FILM_READY = true;
```

URL 参数就是调试接口：

| 参数 | 作用 |
|---|---|
| `scale=1/2` | 内部超采样（预览 1、成片 2） |
| `frame=N` / `t=秒` | 打开时显示哪一帧 |
| `test=1&cam=x,y,z&at=x,y,z&fov=35` | 自由机位 |
| `k=&elev=&az=` | 覆盖光照（test 模式） |
| `<部门>=0` | 跳过某个部门（定位问题） |
| `pose=` `yaw=` `eyes=` `beacon=`（Sunshower） | 直接摆机器人姿势 |
| `kfhide=plumage,wings` | 隐藏翠鸟的部分（调试） |
| `headless=1` | 无头模式（不自动画首帧） |

**部门容错加载**：每个部门模块独立 `import`，崩了就退化成 `{ update() {} }` 并打印错误 —— “so the others can keep rendering”。8 个 agent 同时改代码时，一个人的语法错误不会让所有人都看不到画面。

**预热帧**：“the very first render after load differs slightly (lazy GPU state); render once and discard so every captured frame is deterministic”。

## 7.3 渲染器（`render.mjs`）的工程细节

这是整个项目里**最“生产级”**的代码，值得逐条学习：

1. **分段 + 续渲**：帧按 `--seg`（默认 144 = 6 秒）分段，每段写 `seg_XXXXX.mp4` + `.json`（范围、编码参数、源码哈希、字节数、秒/帧）。重跑同一命令，完整的段直接跳过。Ctrl+C 最多丢失正在渲的那一段。
2. **源码哈希防“混剪”**：对 `src/` 和 `index.html` 取 SHA1。“Segments rendered from different sources are re-rendered by default so the film never mixes old and new drawings”。
3. **加载报错即停**：页面加载时有任何 console error（比如某部门模块导入失败）就拒绝渲染 —— “a film silently missing its kingfisher is worse than no film”。
4. **帧数校验**：每段用 `ffprobe -count_packets` 校验帧数；拼接后再校验总帧数；混音后再校验一次。
5. **正确的色彩矩阵**：Chrome 的 JPEG 是 full-range BT.601，而 HD 视频应标 limited-range BT.709：

   ```
   -vf format=gbrp,scale=out_color_matrix=bt709:out_range=tv:flags=lanczos+accurate_rnd+full_chroma_int,format=yuv420p
   -colorspace bt709 -color_primaries bt709 -color_trc bt709 -color_range tv
   ```
   不做这一步，成片在浏览器里会偏色/发灰。

6. **x264 参数**：`-preset slow -tune animation -crf 16 -g 48`（`-tune animation` 对大色块、硬边更友好）。
7. **音画对齐**：音轨按渲染的帧范围裁切（支持 `--ranges` 局部渲染），再 `apad` / `atrim` 到**精确的画面长度**（不用 `-shortest`，“a short soundtrack must never cut frames off the end of the film”）。
8. **WebGL 上下文丢失检测**、**孤儿 Chrome 回收**（记录 pid + profile 目录，下次启动时只杀确认是自己的那个进程）、**失败段重试 3 次**、多页并行（实测没更快：“JPEG capture + x264 are the bottleneck”）。

anime-core 的 `render.mjs` 保留了 1、3、4、5、6、7，去掉了源码哈希、多页并行和孤儿回收（约 100 行），已验证：192 帧分 4 段渲染、拼接、混音，输出 192 帧 / 8.000 s。

## 7.4 交付：一个 HTML 文件就是一部片

`build-player.mjs`：

1. 主片（crf 16，带逐帧颗粒）可能很大；超过 `--max-mb`（默认 60）就用**两遍编码**按码率压到预算内（缓存在 `out/delivery/web/`）—— 保证页面 < GitHub 单文件 100 MB 上限。
2. 海报：按**影片帧号**从母版精确截取（通过 render 写的 manifest 把影片帧映射到视频帧，局部渲染也能用），默认取彩虹镜头 67% 处。
3. MP4 → base64，写进 `<script type="text/plain" id="reel">`（按 3 MB 分块写，3 的倍数保证 base64 能无缝拼接）。
4. 页面打开时分块 `atob` 成 `Uint8Array` → `Blob` → `URL.createObjectURL`（支持 `Uint8Array.fromBase64` 的新浏览器走快路径），页面不卡。

播放器（`player/player.html`，26 KB）：标题卡 → 自动播放（被浏览器拦截则静音播放 + “开启声音”胶囊）、自定义进度条、全屏、键盘快捷键、`prefers-reduced-motion`、**播放器端再叠一层实时胶片颗粒**（视频里的颗粒被编码器抹平了一部分）、结束卡片。

anime-core 有一个 70 行的精简播放器模板，已验证：14.4 MB 的 `dist/star.html` 在 Chrome 中解码成功、`video.duration = 8`、无页面错误。

## 7.5 平台差异：原作是在 Windows 上做的

| 位置 | 原作写法 | 在 Linux / WSL 上 |
|---|---|---|
| `env.mjs` Chrome 参数 | `--use-angle=d3d11` | D3D11 只存在于 Windows。Linux 用 `swiftshader`（CPU 软件渲染，需 `--enable-unsafe-swiftshader`）或有 GPU 时 `gl` / `vulkan` |
| `env.mjs` Chrome 路径 | 平台默认路径 | 用 `CHROME=/path/to/chrome` |
| `render.mjs` 孤儿回收 | `powershell` + `taskkill`（win32 分支）；Linux 分支读 `/proc/<pid>/cmdline` | Linux 分支可用 |
| `render-audio.mjs` 频谱标注字体 | `C:/Windows/Fonts/arial.ttf` | 需改成 Linux 字体路径 |
| `textures.js` 日文字体 | `"Yu Gothic", "Meiryo", "MS Gothic"` | Windows 字体，Linux 上回退 → 机器人身上的日文字会变 |
| 换行符 | LEVIATHAN 是 CRLF | `diff` 要加 `--strip-trailing-cr` |
| 深路径 | “On Windows, deep project paths can hit MAX_PATH: install it elsewhere and point TOOLS_DIR there” | — |

anime-core 的 `env.mjs` 已经按平台选 ANGLE 后端（`ANGLE` 环境变量可覆盖），并支持 `TOOLS_DIR` 找 puppeteer-core。

**性能参考**（本机实测，WSL2 + Chrome 157 + SwiftShader 纯 CPU）：示例片 `scale=1` 约 **2.3 秒/帧**，8 秒短片 192 帧共 447 秒。原作在 Windows GPU 上的预算是 `scale=2` 下 ~0.4 秒/帧。**做长片务必用 GPU**（Windows 原生 Chrome + D3D11，或 Linux 上可用的 GL/Vulkan）。

## 7.6 静帧自审循环（工具链的真正目的）

```
改代码 → node tools/check.mjs（零报错？）
      → node tools/snap.mjs --sheet review s:镜头A s:镜头B t:关键时刻 ...
      → 用 Read 工具打开 JPG，“critically judge”：构图？接触？比例？颜色脏不脏？线条读不读得出？
      → 和参考帧对比（LEVIATHAN：ref/ 目录里每个镜头的参考截图）
      → 存当前最好的到 out/<部门>/latest/（“the client asks to see progress”）
```

我在做 anime-core 示例时完整走了这个循环 5 轮，每一轮都靠静帧发现了“读代码看不出来”的问题：镜头全被悬崖挡住、颜色发灰、地平线黑带（NaN）、闪光被海床切掉、流星在白云前隐形。详见 [10](10_示例引擎使用说明.md)。
