# 01 项目全景与谱系

## 1.1 两部片子各是什么

| | Sunshower · 狐の嫁入り | LEVIATHAN · リヴァイアサン |
|---|---|---|
| 时长 / 帧数 | 42 s / 1008 帧 | 83 s / 1992 帧 |
| 规格 | 24 fps，1920×1040（≈1.85:1 院线比例） | 同左 |
| 镜头数 | 10 | 39 |
| 场景（set） | 1 个：被淹没的夏日东京 | 8 个：coast / deck / sky / orbit / ocean / bridge / under / port |
| 主角 | AV-98 英格拉姆（同人致敬）+ 一只翠鸟 | 110 m 银色弓兵机甲 + 900 m 利维坦 + 300 m 集装箱船队 |
| 情绪 | 温柔、明亮、怀旧、小幽默 | 史诗、尺度、冲击 |
| 源码规模（src/） | ≈14.7k 行 JS | ≈19.4k 行 JS |
| 交付 | `dist/sunshower_lite.html` 26 MB（单文件，离线可看）；完整版约 78 MB | `dist/leviathan_lite.html` 26.6 MB |
| 做法 | Claude Code：导演会话 + 并行部门 agent | 同左，且明确“改编自 AHMII 的短片，逐镜头重绘为明亮赛璐璐风” |

**故事梗概**

- *Sunshower*：一台警用机器人齐腰站在被淹没、长满植被的东京里，左手托着一只翠鸟。太阳雨（狐の嫁入り）落下，机器人把右手举过翠鸟头顶当伞；雨停，彩虹升起，翠鸟飞向彩虹，机器人轻轻挥手。
- *LEVIATHAN*：巨大的弓兵在海岬上拉开巨弓，箭直冲轨道。海上，船队旁浮起四头鲸 —— 它们其实是利维坦口中的诱饵。箭从太空折返，带着闪电贯穿巨兽，海水吞没船队。

## 1.3 共用了什么、改了什么（逐文件 diff 结果）

用 `diff --strip-trailing-cr` 对比两个仓库（LEVIATHAN 是 CRLF 换行，Sunshower 是 LF）：

| 文件 | 结果 |
|---|---|
| `src/engine.js` | **仅 1 行不同**：LEVIATHAN 给 `setupShadow` 传了 `opt.shadow.depth`（大场景需要更深的阴影相机） |
| `src/glsl.js` `src/materials.js` `src/util.js` `src/tex-foliage.js` | **完全相同** |
| `tools/snap.mjs` `check.mjs` `probe.mjs` `env.mjs` `sheet.mjs` `player/test-player.mjs` | **完全相同** |
| `tools/render.mjs` / `build-player.mjs` | 只改了默认文件名和海报帧 |
| `src/passes-env.js` | LEVIATHAN 加了 `OCEAN_GLSL`（千米级海洋）、船尾迹、海中巨影、“海天交界融化”雾 |
| `src/look.js` | 只换了调色板数值 + 加 `fogDensity/ocean/oceanScale` 等覆盖项 |
| `src/main.js` | 部门列表不同；LEVIATHAN 加了 `registerCams()`（每个部门自己管自己镜头） |
| `src/shots.js` | 完全重写（这是“故事”本身） |

还有一个“化石证据”：LEVIATHAN 的 `index.html` 标题仍是 `Sunken Patrol — workbench` —— Sunshower 的工作名。

**结论：两部片 = 同一个引擎 + 两套内容。** 引擎可复用性已经被实战证明。

## 1.4 谱系：Moss Keeper → Sunshower → LEVIATHAN

```
The Moss Keeper（ChetasLua，"Made with Fable 5.5"）
  │  一个 48 MB 的 index.html：base64 MP4 + 自定义播放器 + 实时胶片颗粒
  │  —— 证明了“单文件交付一部片”的形式
  ▼
Sunshower（Beyond Dev，Claude Code）       README: "Inspired by The Moss Keeper"
  │  建立了整套引擎：MRT + Kuwahara + 描线 + 屏幕空间水 + 程序化音频 + 续渲工具链
  │  建立了制作方法：CONTRACT + 部门 agent + 静帧自审
  ▼
LEVIATHAN（Beyond Dev，Claude Code）       CONTRACT: "engine and tooling come from our previous film"
     复用引擎，扩展到 8 个场景、千米尺度、39 个镜头
     新增：GPU 弯曲的 900 m 生物、千米海洋、能量特效、按镜头分部门的镜头注册表、
           对照参考片做音频响度/频谱比对
```

本仓库同目录下的 `moss-keeper-main/` 只有 `index.html`（48 MB）和 README，没有源码 —— 它是交付形式的参照，不是技术参照。

## 1.5 关键数字（对做引擎有用）

| 项 | 数值 | 来源 |
|---|---|---|
| 单帧预算 | “typical frame under ~0.4 s at --scale 2”（有 GPU 时） | LEVIATHAN CONTRACT |
| 内部超采样 | 预览 `scale=1`，成片 `scale=2`（3840×2080 内部渲染，最后 4 点平均） | engine.js FINAL_FS |
| 阴影图 | 4096²，只渲染角色根节点 | engine.js |
| 反射图 | 半分辨率 | engine.js |
| 视深度 > 8000 m | 视为天空 | 所有后期 pass |
| 拍数 | 角色 12 张/秒（一拍二），水/能量特效 8 张/秒（一拍三） | util.js `onTwos/onThrees` |
| 渲染分段 | 默认 144 帧（6 s）一段，可续渲 | render.mjs |
| 编码 | x264 `-tune animation -crf 16 -preset slow`，BT.709 limited | render.mjs |
| 交付压缩 | 超过 60 MB 时两遍编码压到预算内（GitHub 单文件 100 MB 上限） | build-player.mjs |
| 音频 | 48 kHz / 16-bit，-16 LUFS（Sunshower）/ -14 LUFS（LEVIATHAN），峰值 -1.5 / -1.85 dBFS | audio.js |

## 1.6 我在本机的验证情况

- 两个原仓库没有 `node_modules`，也没有 `out/`（渲染产物不入库）。我**没有**重新渲染原片（原工具链默认 Windows + D3D11，见 [07](07_工具链与交付.md)）；对原作的结论来自逐文件阅读源码 + 仓库自带的 `docs/*.jpg` 成片截图。
- 我把共用引擎抽象成 `anime-core/`，**在本机（WSL2 Linux，Chrome 157 + SwiftShader 软件 WebGL）实际跑通**：加载零报错、静帧、配乐 WAV、整片 MP4、单文件播放器。详见 [10](10_示例引擎使用说明.md)。
