# 04 角色与资产建模：没有一个外部模型文件

> 对应原作：Sunshower `robot.js`、`textures.js`、`kingfisher3d.js`、`kf3d-*.js`、`world.js`、`bgmaterials.js`、`tex-foliage.js`；LEVIATHAN `archer-geo.js`、`archer-model.js`、`archer-mat.js`、`lev-body.js`、`lev-limbs.js`、`lev-whale.js`、`ships-*.js`、`world-sky.js`。
> 对应 anime-core：`src/core/kit.js`（hull / cbox / superPts / blob / spike / Rig / solve2），`src/story/dino.js`。

两个仓库里**没有任何 .glb/.fbx/.obj/.png 资产**（docs/ 里的 jpg 是成片截图）。所有几何、贴图、字、花纹都是代码生成的。这对“AI 做动画”意义重大：**资产 = 代码 = 可以被 AI 读、改、diff**。

## 4.1 硬表面角色：点集 → 凸包

Sunshower 的机器人（`robot.js`）只用了几种“造型原语”：

| 原语 | 作用 | 实现 |
|---|---|---|
| `cbox(w,h,d,c,{wt,dt,zt})` | 带倒角、可收分（顶面宽深不同）、顶面可前后偏移的盒子 —— 装甲板 | 24 个点 → `ConvexGeometry` |
| `superPts(rx,ry,rz,e,n,fn)` | 超椭球点集，`e=2` 椭球、越大越方；`fn` 可以把点**夹到切平面**再求凸包 | 肩甲：`q.y = clamp(q.y, -0.38, 0.47)` → 顶面平（放信标灯条），外侧平（放涂装） |
| `hull(points, crease)` | 任意点集的凸包 + 折角法线 | `toCreasedNormals(g, 34°)`：小于 34° 的面平滑、大于的保持硬边 |
| `blade(len, w0, w1, ...)` | 三圈截面点的凸包 —— 天线 | |
| `rbox` / `cyl` / `bentPlane` | 圆角盒、圆柱、弯曲平面（画玻璃反光） | three 内置 + 少量改造 |

为什么是凸包：**任意形状都能由“我想要这几个角”描述出来**，不需要拓扑、不需要 UV。AI 写 `v(sx*0.62, 0.78, 0.82)` 这样的点非常自然。代价是只能表达凸形 —— 凹形用多个凸零件拼（这本来就是机甲装甲的结构）。

> LEVIATHAN 发现的坑（`archer-geo.js`）：“three's crease hash truncates at 0.01: work at x30 so tiny hand parts keep clean normals” —— 小零件先放大 30 倍算折角法线再缩回。anime-core 的 `creased()` 已包含。

**骨架 = Group 树**：`joint(name, parent, pos)` 建关节，`part(geo, opts, joint, pos, rot)` 挂零件，零件材质自动分配循环的描线 id（相邻零件 id 不同 → 接缝处自动出线）。

**锚点（anchors）**：`antennaTip, nest, visor, lightbarL/R, shoulderL/R, elbowL/R, wristL/R, handL/R, chest, pelvis, footL/R, perchL（翠鸟的座位）, palmL, roofR（伞手掌心）, tipL0..3, thumbTipL…` —— 其他部门只读锚点，“always read anchors, never hard-code positions”。设计还在改的时候，特效和鸟都不会错位。

## 4.2 规模化：LEVIATHAN 的“铠甲工具箱”

弓兵 110 m 高，近景要看到螺栓。`archer-geo.js` 的做法：

1. **先雕身体曲面**（tube），再在上面**贴重叠的曲面甲片**（patch，带倒角边）—— “the way real armour is”。
2. 每个关节下的**所有甲片合并成一个网格**，每个顶点带 `aCol`（颜色）、`aMat`（金属度、细节量、自发光类型、描线 id）、`aEx`（边缘、磨损）—— “so 2000 plates cost a handful of draw calls”。
3. 风格表 `STY = { PALE, SILVER, STEEL, BLUESTEEL, GUN, DARK, BRONZE, PISTON, RED, CORE, VISOR }`：每种“漆”是一组 `{col, metal, detail, tone, wear, emis}`，零件只说“我是 SILVER”。
4. **面板细节图集** `makePanelAtlas(2048)`：一张可平铺的“动画色指定表”风格面板图：递归面板缝、色块、内嵌舱盖、通风口、螺栓、手写编号、警示斜纹。每 3.4 个单位平铺一次；**近景再叠一层 3.3 倍细的同一图集**（`smoothstep(95, 34, depth)`）—— “macro shots stay dense”。
5. 磨损边：甲片边缘露出亮金属（`bare = mix(col, vec3(1.06,1.04,1.0), 0.8)`）——“the signature of the reference”。

客户两次否决了“干净、方块、Minecraft”的外观，CONTRACT 写进了硬要求：“Dense detail and real volume … Silhouettes must be sculpted; surfaces carry panel lines, bolts, markings, wear.”

## 4.3 贴花与手写字（`textures.js`）

**投影贴花**：`celMaterial` 支持两张贴花，每张沿零件的一个局部轴投影（`axis 0|1|2, sign ±1, rect [cu,cv,w,h]`），只在朝向该轴的面上显示（`face * sg < 0.25` 时丢弃）。效果：涂装文字能**绕着弯曲的装甲**贴，而不用 UV 展开。

**手写英文字母**：
```js
const GLYPHS = { A: [0.62, [[[0,1],[0.31,0],[0.62,1]], [[0.13,0.64],[0.49,0.64]]]], ... };   // 字形骨架
function brushStroke(g, pts, width, rng) {  // Catmull-Rom 平滑（尖角保持尖）→ 沿路径密集打“墨点”
  const taper = Math.min(1, u / 0.08, (1 - u) / 0.1) * 0.35 + 0.65;   // 起笔收笔变细
  const w = width * press * taper * (0.92 + 0.16 * Math.sin(u * 9 + press * 7));   // 笔压起伏
}
function letter(g, text, x, y, h, rng, { slant, track, squash }) { /* 每个字随机抖动位置/大小/倾斜 */ }
function handPaint(c, seed, amp, erode) { /* 整张图用低频噪声扭曲 + 侵蚀边缘：像刷在金属上的油漆 */ }
```
目标：“Everything is drawn like an animation colour-key sheet, then roughened so nothing looks typeset.”

**日文（警視庁、特車2-1、特車二課、止まれ）** 用的是 `canvas.fillText` + 系统字体 `"Yu Gothic", "Meiryo", "MS Gothic"` —— 这些是 **Windows 字体**。在 Linux/WSL 上会回退到别的字体（或缺字）。**这是一个跨机器不确定性来源**：做引擎时应把字体文件随项目分发（或把需要的字预先烘成路径数据）。

## 4.4 有机角色：翠鸟（`kingfisher3d.js` + `kf3d-*.js`）

- **羽毛体 = 一个连续曲面**：头（圆）+ 身体（胖水滴）的 **SDF 平滑并集**，从颈部内的一点沿射线采样表面得到网格（“no neck”）。
- **蒙皮**：每个顶点有“头部权重”，每帧在身体变换和头部变换之间混合，并带**扭转 slerp** —— 头能转到背后而脖子不塌。
- **蓬松/湿透/炸毛**：沿静止法线方向的偏移（`puff / sleek / fluff`）。
- **颜色花纹**从 `aRest` 读，所以羽毛的橙色带、蓝色背不会随动作游走。
- **眼睛**：眼球“朝镜头转”以保证有高光点；闭眼、眯眼、开心 `∩` 是**画出来的线条**（材质里的笔画），不是 3D 眼皮。这是动画眼睛的标准画法。
- 描线 id：90 身体、91 喙、92 眼、93 翅膀和尾、94 脚、95 水。

## 4.5 巨型生物：利维坦（`lev-body.js` + `lev-mat.js`）

- **放样（loft）**：沿 z（尾 → 吻）用若干条 Hermite 曲线定义截面宽、背高、腹深、唇线（`K.xw / ty / by / lip`），一圈圈超椭圆截面连起来 → 一整张皮。
- **沿唇线切开**，下半部顶点带下颌权重 → 嘴真的能张开；口腔内衬一直延伸成喉咙；牙龈、牙齿、骨刺、眼睛是附加零件。
- **皮肤全部在片元着色器里画**：鳞甲图案 + **凹凸法线让明暗分界沿鳞甲断开**（“the terminator breaks along the scutes”）+ **每块鳞甲一个材质 id** → 描线 pass 真的给每块鳞描边。部件类型 `part: 0 皮 1 牙 2 口腔 3 骨刺 4 爪 5 眼 6 蹼 7 茎 8 鲸 9 舌 10 牙龈`。
- 鳍与尾鳍：`addBlade(planform)` —— 给出平面轮廓（前缘/后缘/厚度随长度变化），生成透镜截面的叶片；挂在身体脊柱上的独立短链。
- 诱饵鲸：同一套方法做的 120 m 座头鲸（`lev-whale.js`），带“颈”（诱饵的长茎）。

## 4.7 给新引擎的建模规范（建议）

1. **一切造型用代码原语**：`cbox / blob(超椭球) / spike / hull(点集) / loft(截面+曲线) / blade(平面轮廓)`。anime-core 的 `kit.js` 已有前五个。
2. **零件多、draw call 少**：同一关节下的零件合并，参数走顶点属性（参考 LEVIATHAN `Kit`）。
3. **花纹和风化用“静止坐标”计算**（`aRest` 或物体局部坐标），永远不要用世界坐标（会游走）。
4. **每个角色发布锚点清单**，写进 CONTRACT。
5. **文字**：拉丁字母用骨架笔画（可移植），CJK 字用随项目分发的字体文件。
6. **描线 id 规划表**写进 CONTRACT（谁用哪一段）。

## 4.8 anime-core 的有机建模层（已实现，2026-11-05）

第一版示例里的星星恐龙用的是 4.1 的“硬表面”方法：约 40 个 `blob/cbox/spike` 零件拼起来。成片里能明显看出问题：
- 头、脖子、身体像几个球粘在一起，接缝处都有描线；
- 奶油色肚皮是一块贴上去的零件；
- 尾巴一节一节的；
- 眼睛只是一个黑色小球。

**根本原因是选错了方法。** 凸包拼零件适合机甲，因为装甲本来就是一块块拼的；有机角色应该走 4.4 翠鸟的路线。所以把翠鸟的方法泛化成了引擎能力，放在 `core/` 下：

| 模块 | 原作出处 | 泛化了什么 |
|---|---|---|
| `organic.js` `SoftBody` | `kf3d-plumage.js`（头 + 身体的 SDF 平滑并集） | 原作只有两个团块，靠“从颈部内一点打射线”采样表面，只适用于星形的形体。这里改成：任意多个椭球、圆锥台图元做平滑并集，用 **Surface Nets** 网格化，顶点再用牛顿步投影回精确表面，法线取 SDF 梯度。长尾巴、腿脚都能用 |
| `organic.js` `Skin` | `kf3d-plumage.js`（头部权重 + 两变换蒙皮） | 原作只在“头/身体”两个变换之间混合。这里扩展到**任意多骨骼**：每个图元挂在一根骨头上，顶点对每根骨头的权重由“到该骨头名下图元的距离 − 最近距离”决定，取前 4 个做 CPU 线性混合蒙皮 |
| `organic.js` `surf / stroke` | `kf3d-geo.js` | 原样移植：参数曲面（法线由同一函数差分得到）、两端收尖的笔画管 |
| `celMaterial({ pattern, rest })` | `kf3d-geo.js` `kfMaterial`（字符串替换着色器） | 改成 celMaterial 的正式选项。花纹用 GLSL 按静止坐标 `aRest` 计算，返回颜色和“不受光比例” |
| `face.js` `createEyes` | `kf3d-model.js` 眼睛 + `kingfisher3d.js` `aimEyes` | 眼球位置沿射线找头皮，眼窝坐标系自动生成；闭眼、笑眼、眯眼的笔画在眼窝切平面上画好，再投影回头皮 |
| `kit.js` `starPlate` | — | 新增：圆角五角星挤出的骨板 |
| `color.js` `screen()` | — | 新增：反解最终调色，让“屏幕色”变成管线输入色（见 02 §2.11 的颜色空间陷阱） |
| `tools/turnaround.mjs` | 原作的静帧自审 | 新增：一条命令出转面图（正面/四分之三侧/侧面/背面）和表情表 |

**星星恐龙**（`src/story/dino.js`）就是用这一层建模的：
- 身体、脖子、头、口鼻、腮帮、腿脚和整条尾巴由 17 个图元组成同一张皮（约 3.6 万顶点），9 根骨头自动蒙皮；
- 奶油色肚皮、喉咙和下颌是一整块花纹，嘴线正好是“上颌薄荷绿 / 下颌奶油色”的分界线；张嘴时在嘴线下方挖出口腔和舌头；
- 鼻孔和腮红是以表面点为中心的贴花；
- 只有星形骨板和小手是独立零件：骨板是硬的，小手需要转 110°，线性蒙皮扛不住。

迭代中发现的坑（都是看静帧才发现的）：

1. **相邻圆锥台不要用大的融合半径。** 尾巴各段在关节处半径相等，本来就是连续的；k=0.12 的平滑并集反而在关节处鼓出一圈，法线起伏使背脊色带断断续续，看起来是一圈圈条纹。k 降到 0.03 后消失。
2. **大而平滑的皮肤，阶跃高光会铺成一大片。** 头部半径 0.8 m 时，`N·H > 0.985` 覆盖额头到鼻梁一整条，像一块浅色面具。皮肤 gloss 降到 0.12（接近哑光，符合动画角色皮肤的画法），硬质的星形骨板保持 1.3。
3. **设定图要用正面打光。** 示例片的太阳在角色背后（逆光），自由机位下脸几乎全在暗部，还带一块自投影，没法判断造型。`turnaround.mjs` 默认把主光放在镜头左上方。
4. **设定色必须换算。** 直接写 `#8ad66f`，屏幕上是饱和草绿；用 `screenAll({ body: '#8ad66f', … })` 换算后，平涂处就是薄荷绿。

**什么时候用哪种方法：**
- 圆润的生物：身体、头、尾巴用 `SoftBody`；
- 需要大角度转动的小肢体：用独立的 `SoftBody.geometry()` 或 `surf()`，挂在关节上；
- 硬质的装饰（骨板、角、爪）：用 `starPlate / spike / hull`；
- 机甲：仍然用 4.1、4.2 的凸包和甲片。
